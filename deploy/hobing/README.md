# Unbox package for Hobing

Run `python3 deploy/hobing/package.py --origin https://EXACT-ENVIRONMENT-ORIGIN --output .cache/hobing/NEW-DIRECTORY` from the project root. The output directory must not already exist. The tool uses the locally retained 0.2.21 metadata, signed packages, and signatures in `.cache/cloudflare`; it does not create or publish a new release.

The package contains a bundled `worker.mjs`, the two namespaced SQL migrations, and `objects/` with R2 keys and an `objects.json` inventory of content types, byte lengths and SHA-256 digests. Apply migrations to the site's isolated D1 and upload objects with their listed metadata to the site's isolated R2. The worker requires D1 binding `DB` and R2 binding `FILES`; no secrets are required. Set `PUBLIC_ORIGIN` to the exact HTTPS site origin so alternate project addresses redirect to the same site and download URLs. Seed a separate package for each exact origin: download redirects require manifest URLs on that origin. Do not replace the Printoria release manifest; existing clients continue to use it.

Register `https://EXACT-ENVIRONMENT-ORIGIN/unbox/auth/callback` as a Single-page application redirect on the existing Microsoft app before testing sign-in. Existing users must sign in again on a new origin. Preserve existing feedback records through a separately verified migration; these schemas alone create empty tables. Do not copy active sessions or flow records. Root redirects to `/unbox/`, preserving the existing site, API, cookies and callback paths.

The package is a local artifact only. Verify migrations, object checksums, range requests, both download redirects, and real Microsoft login in staging before production cutover.

For Hobing, run `python3 deploy/hobing/deploy-preview.py --api https://API-ORIGIN --site-origin https://SITE-ORIGIN --project PROJECT-ID --package .cache/hobing/NEW-DIRECTORY`. The default environment is preview; `--environment production` must be supplied explicitly for production. It checks the package's release URLs against the specified site origin and prompts for an owner or scoped agent token without placing it in command arguments; `--token-stdin` accepts a token via standard input. It provisions resources, applies migrations, verifies existing object hashes, uploads missing objects (multipart for large files), reads each upload back to check SHA-256, and prepares an immutable Worker deployment. It stops if an existing object differs. It never activates a deployment unless `--promote` is explicitly supplied. Resume interrupted multipart uploads through Hobing's upload API before rerunning. Production cutover and feedback migration are separate operations.
