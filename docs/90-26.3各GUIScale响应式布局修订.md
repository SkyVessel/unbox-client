# 26.3 各 GUI Scale 响应式布局修订

日期：2026-11-11。用户指出上一轮把整张 1440×810 画布缩到中间，破坏了侧栏贴边、背景覆盖窗口等结构；并明确各档位还需要调整留白、比例和内容密度。

## 本轮布局

- Auto 保留原设计的默认尺寸。控件密度随 GUI Scale 渐进变化，使用选中档位与 Auto 比值的平方根，降低小档位过度缩小的问题。
- 可用布局区域始终覆盖整个窗口。主菜单底板按窗口扩展，保留圆角和内边距；账号栏固定左上，退出固定左下，中央操作组保持居中。
- 快捷菜单好友面板接到窗口右边及上下边缘，曲线边缘保持形状，扩大的是中间连续部分。人物、中央操作和好友栏重新分配空间；人物预览高度根据可用高度有限增长，Change skin 按钮继续跟随人物下沿。
- 好友面板宽度随可用空间有限增加，列表可见行数根据高度计算，分页位于最后一行下方，给曲线留出余量；邀请状态与错误提示放在好友标题附近。右侧操作保持靠右，较长列表不会超出面板。
- Mods 面板覆盖可用区域；列数由可用宽度决定，卡片宽度分配剩余空间，可见行数随窗口高度改变。低 GUI Scale 可以看到更多模块，仍保持卡片、文字、开关的结构。
- Mods 透明度标尺随面板高度延伸，右上换色弧线保持靠右，列表裁剪与交互坐标使用同一个布局尺寸。列表无需滚动时完整展示，需要滚动时保留平滑循环。
- Appearance 保持外层完整底板，内部皮肤、预览与资产分区重新定位，相关标题、操作和内容保持在同组。
- 保留两种配色、独立背景透明度、Logo 镂空、曲线吸附、分类过渡与 Reduce motion。

## 实现与验证原则

`SolidLayout` 负责区域定位、面板边界和内容密度。SVG 缓存、原生控件、动态人物、列表纹理和命中区域使用一致的布局。背景形状按可用区域重建，未把完整页面当作图片拉伸。

上一轮“整页物理占比变小”的验收条件不足。本轮改为检查侧栏是否贴边、底板是否覆盖窗口、各控件是否落在可用区域、列表是否重排，以及重排后原生按钮能否正确操作。

`SolidLayoutTest` 在六种窗口尺寸和多种密度值下检查区域关系，并读取实际打包 SVG 验证好友面板上下边缘与主菜单底板覆盖。`SolidVisualTest` 继续检查透明度隔离、Logo 与曲线。

原生菜单矩阵覆盖两种配色、Auto / 2 / 1 档位及 Title / Quick / Mods / Appearance，使用 18 个虚拟好友验证长列表布局；随后执行模块设置、搜索、好友/皮肤回执、滚动与分类过渡检查。数据仅存在于隔离测试 Profile，没有向真实账号发送请求。

不创建、不进入世界，不测试游戏视角。Windows/Linux、真实世界背景下的主观视觉体验留给用户实测。

## 复现

```sh
python3 scripts/prepare-solid-ui.py
UNBOX_MINECRAFT_VERSION=26.3 sh scripts/build-mod.sh
UNBOX_MINECRAFT_VERSION=26.3 python3 scripts/build-neoforge-mod.py
python3 scripts/test-solid-ui.py --loader fabric --layout-checks --name fresh-layout-fabric
python3 scripts/test-solid-ui.py --loader neoforge --layout-checks --name fresh-layout-neoforge
npm run tauri -- build --debug --bundles app
```

每次测试使用新目录，两种加载器顺序运行。交付应用为 `src-tauri/target/debug/bundle/macos/Unbox Client.app`，仅 26.3 使用本轮布局。未发布 Release。

## 最终结果

- Fabric 最终交付 JAR 通过 482 条布局与菜单断言；NeoForge 通过 466 条。两种加载器各保存 37 张截图，实际运行 JAR 与 App 内交付 JAR 哈希一致。
- 原生矩阵实际帧缓冲：Fabric 3840×1916（系统限制窗口高度），NeoForge 1920×1080；后续改尺寸检查均含 1686×958。没有将窗口检查描述为 3840×2160 全屏实测。
- 离线布局检查含 3840×2160、2560×1600、1686×958、1280×1024、854×480、3440×1440 和各自多档密度，共 318 项；透明度、Logo 与曲线 355 项；源码隔离回归 5 项，均通过。
- 本地 macOS App 打包通过。六个内置模块与对应资源 JAR 哈希一致，只有 26.3 包含响应式布局；两种加载器的矢量资产均与当前源资源一致。
