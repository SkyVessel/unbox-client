# 0.2.10 Windows 控制台修复与发布

2026-10-19，用户授权修复 Windows 启动器和后台进程黑色控制台窗口，并发布可由启动器更新的新版本。

## 根因与修改

0.2.9 的 Windows EXE 实际 PE 子系统为 3（Console）。代码只在非 debug 构建指定 Windows GUI 子系统，而发布渠道使用 debug 构建，因此仍生成控制台窗口。现改为所有 Windows 应用构建均使用 GUI 子系统，测试程序保留测试运行器的正常行为。

新增 `src-tauri/src/process.rs`，为标准及 Tokio 后台进程统一设置 Windows `CREATE_NO_WINDOW`。所有应用侧进程入口均已接入：Java 版本探测、Minecraft 启动、NeoForge 安装、共享目录 junction 创建、浏览器/目录/许可页面打开。保留 stdout/stderr 重定向和现有日志路径。该标志只禁止控制台，不隐藏 Java 游戏等正常 GUI 窗口。

依据：[Microsoft Process Creation Flags](https://learn.microsoft.com/en-us/windows/win32/procthread/process-creation-flags)。Tauri updater 的 Windows 安装入口使用 ShellExecuteW，未引入自定义安装流程。

## 验证与发布结果

Windows 新增两项实际子进程检查：通过同步和异步入口启动独立测试进程，调用 GetConsoleWindow 确认无控制台，同时确认 stdout/stderr 可读取。该子进程 probe 仅由这两项检查显式执行，不在普通测试循环中单独运行。

工作流构建后检查真实启动器 EXE 的 PE 子系统必须为 2（GUI）。本轮不修改游戏 Java 功能，仅将六种模块版本元数据同步到 0.2.10。以下为最终构建与公开附件检查结果。
