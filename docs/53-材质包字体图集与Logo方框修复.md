# 材质包字体图集与 Logo 方框修复

2026-10-19，目标版本 0.2.14。用户在 Windows 看到姓名牌 Logo 显示为空心方框，并确认开启材质包时触发。

## 原因

旧版皇冠和现金的 bitmap font 直接引用 512×512 的 UI 图片。Minecraft 默认字体图集为 256×256，字体 JSON 的 `height:12` 仅决定显示尺寸，不会缩小待装入图集的源像素。过大的字形无法装入后回退为缺字方框。

此前 macOS 的测试启用了 ImmediatelyFast 默认的 1024×1024 图集，掩盖了资源尺寸缺陷。该模组检查材质包覆盖的核心文字着色器；未声明兼容字体图集扩展时，临时关闭扩展并重新加载字体。这个回退暴露了 Unbox 的超尺寸字形。没有修改权限、UUID 同步或材质包开关。

依据为本地已使用的 Minecraft 26.1 / 26.3 `FontTexture`、`GlyphStitcher`、`BitmapProvider` 与 ImmediatelyFast 1.17.1 的 `MixinMinecraft.checkResourcePackCompatibility` / `MixinFontTexture` 字节码，以及实际隔离游戏复现日志。没有拿到用户的具体材质包，使用独立文字着色器覆盖夹具复现同一兼容路径；夹具不覆盖任何 Unbox 资源。

## 修复

- 从已采纳的 SVG 单独导出 128×128 透明姓名牌纹理，保持设计、颜色和显示大小。UI 仍使用原 512×512 图片，原 SVG 未修改。
- 字体定义指向专用 `textures/font/` 资源；无需依赖图集扩展，保留材质包兼容回退机制。
- 六套 JAR 发布检查逐项验证 bitmap 字形尺寸不超过原版 256×256 图集。
- 实际游戏回归由“字符宽度大于零”改为对照缺字字形，检查基础、皇冠、现金三种字形真正烘焙成功。

## 验证与边界

- 默认 256 图集下：0.2.13 实际截图出现方框；修复版 87 项视觉检查通过，皇冠姓名牌正常。
- 开启文字着色器覆盖材质包：旧版出现同样方框；修复版截图显示皇冠，日志确认 ImmediatelyFast 兼容回退仍然触发。完整回归报告保存在证据目录。
- 六套原生 Fabric / NeoForge 模块构建和资源检查通过。与 0.2.13 逐条目比较，差异限于字体资源、回归辅助代码和版本元数据；其他游戏逻辑保持一致。
- macOS 68 项原生测试、前端构建通过；macOS 更新包已签名并核对 45 份内嵌资源。
- Windows 构建与公开更新附件尚待后续验证。未进行 Windows 游戏实玩，也未直接测试用户的具体材质包。
