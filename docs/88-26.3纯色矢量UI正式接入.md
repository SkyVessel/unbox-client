# 26.3 纯色矢量 UI 正式接入

> 后续用户修订已删除 Light 配色并调整透明度、滑块、滚动和 GUI Scale。当前实现与交付证据以 [89 号文档](89-26.3矢量UI交互与透明度修订.md) 为准；本文保留首次接入记录。

日期：2026-11-11。依据用户指定的 [87 号交接](87-游戏内矢量UI实验交接.md)，将实验设计接入正式 Unbox 模块。本轮为本地开发交付，没有发布 Release、修改更新渠道或部署服务。

## 范围

- 26.3 Fabric / NeoForge 原生构建，Light / Red / Yellow 三种配色。标题、Right Shift 快捷菜单、Mods / PvP、好友栏、Appearance、兑换及模块设置接入新界面。
- 使用 `client-mod/src/26.3/java`、`resources` 覆盖层；26.1 / 26.1.2 / 1.21.11 / 1.20.1 不使用新界面。26.1 与 26.1.2 两种加载器的源码生成结果与分支基线一致。
- 保留现有联机世界列表、原版世界选择和游戏设置。它们的入口接通，列表本身不属于 87 号文档的重设计范围。
- ModOptions 的现有模块与完整设置保留。原型六张示例卡片不代表新增玩法需求；正式页面显示实际 Dynamic Lights / Coordinates，不把它们改名为 Fullbright / Waypoints。其他模块通过搜索、翻页进入。

## 已接入的行为

| 页面 / 控件 | 实际行为 |
| --- | --- |
| Title | 单人世界选择、现有多人世界入口、原版设置、Appearance、Client Mods、退出确认；服务器侧栏使用已保存服务器，没有示例服务器 |
| Quick | 返回游戏、设置、Mods、HUD 编辑、实际玩家模型及拖动旋转；世界 / 好友入口 |
| Mods | 真实配置开关、完整详情设置、收藏、搜索、分页、滚轮与拖动滚动条；保留宿主规则和依赖可用性限制 |
| Friends | 实际好友头像与在线状态、分页搜索、接受 / 拒绝、邀请及分享状态；添加代码校验、复制自己的代码、请求中及成功 / 失败反馈 |
| Appearance | 启动器皮肤库、实际皮肤预览、Classic / Slim、明确点击 Use skin 后才应用；Unbox / Crown / Cash 资产按所有权与账号资格装备 |
| Redeem | 保留现有兑换服务和账号资格检查；等待匹配请求 ID 的回执，显示错误 |
| Theme / opacity | 三色选择持久化；背景透明度滑块 30–100%，键盘方向键可调整，文字和控件保持可读 |

皮肤缩略图和身体预览来自真实皮肤库。启动器 `skin_library.rs` 向运行目录发布按内容哈希命名的 PNG 预览，游戏仅接受 64 位十六进制 ID、最大 1 MiB、64×64 图片。选中与应用分开；应用仍走原有账号绑定请求 / 回执协议。

未连接启动器时显示真实空状态；未拥有资产不能装备。没有使用原型的预制 Sent 状态冒充成功。

## 动画与渲染

- 悬停和按压反馈、开关滑动、页面 / 主题切换短距离进入动画、键盘焦点。点击在按钮内释放后执行；组合按钮只保留外侧圆角。
- Reduce motion 及原版屏幕效果关闭时跳过这些动态响应。玩家模型的跟随只作用于 UI 模型，没有修改游戏摄像机输入、平滑或滤波。
- SVG 路径按物理帧缓冲分辨率由单后台线程栅格化，前景与背景分层缓存。动态文案使用 Outfit；原始矢量路径、原生玩家模型和实际头像共同绘制，不宣称所有内容均为矢量。
- 稳定帧不重复生成 / 上传整页纹理；悬停、开关及透明度反馈在绘制阶段完成。窗口改变时旧缓存居中 1:1 显示，等待匹配尺寸的新缓存。
- 离开界面释放纹理、取消后台任务；过期绘制结果不上传。只有物理尺寸匹配、背景完全不透明时才允许跳过世界绘制。透明背景不应用两次 alpha。
- SVG 提取脚本剔除了原型示例人物、皮肤、服务器插图及假业务状态。Outfit 来源和 OFL 随资源保留。

## 构建与本机复现

```sh
# 仅设计导出 / 提取规则改变后运行
python3 scripts/prepare-solid-ui.py

UNBOX_MINECRAFT_VERSION=26.3 sh scripts/build-mod.sh
UNBOX_MINECRAFT_VERSION=26.3 python3 scripts/build-neoforge-mod.py
python3 tests/test_backport_sources.py
cargo check --manifest-path src-tauri/Cargo.toml --offline
npm run build
npm run tauri -- build --debug --bundles app

# 各自使用全新名称，顺序运行，避免两个游戏争用资源
python3 scripts/test-solid-ui.py --loader fabric --name new-fabric-check
python3 scripts/test-solid-ui.py --loader neoforge --name new-neo-check

# 无自动检查属性的独立手动 Profile
python3 scripts/test-solid-ui.py --loader fabric --manual
```

本机调试应用：`src-tauri/target/debug/bundle/macos/Unbox Client.app`。使用此应用启动 26.3，才能同时使用本轮新增的皮肤预览发布功能。不要另装 `unbox-vector-26.3.jar` 原型模块。

## 验证与边界

证据目录：`research/verification/solid-ui-26.3/`，包含两种加载器的原生界面截图、回调断言、构建与回归记录、交付 JAR / 应用内资源哈希。

自动化只在独立虚拟离线账号 Profile 中运行，没有创建或进入世界，没有操作游戏视角。检查覆盖三色六页面、原生鼠标按下 / 释放、Tab / Enter、模块设置与持久化、搜索、改尺寸和 GUI Scale、稳定帧上传次数、不透明判断、未拥有资产限制。

好友 / 皮肤 / 装备检查采用隔离 Profile 内的模拟服务数据和回执：检查真实桥接文件协议、请求 ID、等待状态、错误回显、选皮肤不应用以及成功后的 Equipped 状态。没有向线上账号发送好友请求或装备资产，因此不称为真实账号端到端验收。

本机测试已安装锁定的性能模组组合；没有把此次菜单检查描述成完整生存整合包、世界内玩法、视角体验或所有第三方组合通过。用户明确要求视角自行测试，本轮继续遵守。

NeoForge 本机独立测试 Profile 使用 `earlyWindowControl=false`：默认早期窗口在该机曾卡于 SDL_GL_SwapWindow；这是测试运行目录设置，没有覆盖用户现有 Profile 配置。

Windows / Linux、多硬件、长时间游戏与真实账号跨设备联机仍未在本轮验证。

### 本轮最终结果

- Fabric / NeoForge 的三色完整菜单运行各通过 62 条断言，各保留 24 张原生截图（含三色各六个页面）。
- 最后统一设置页强调色后，两种加载器各通过 44 条针对性断言，分别检查 Yellow / Red 设置页及业务回执。设置页截图明确等待入场动画完成，避免将透明首帧作为最终画面。
- 最终移除 Yellow Mods / PvP 原型残留的两个静态滑块。Fabric 的已通过运行与交付包仅这两张 SVG 不同，全部 class 字节一致；最终资源在两种打包 JAR 中均完成 1686×958 栅格化检查。NeoForge 的最后原生运行 JAR 与交付包 SHA-256 完全一致。各次哈希分别记录，不将旧截图冒充最终包逐像素验证。
- 六个应用内原生模块与对应交付 JAR 哈希一致；只有 26.3 包含新 UI；全部最终覆盖资源与源码资源内容一致。
- 五项源码隔离 / 移植回归测试、Rust 检查、前端构建、本地 macOS App 打包通过。26.1 / 26.1.2 两加载器构建通过。
