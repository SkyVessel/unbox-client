# 1.8.9 Clean Test 与 0.2.25

2026-11-15。用户要求建立最小功能对照环境，并通过更新提供给 Windows。基于已发布 0.2.24 的独立分支 `codex/clean-test-0.2.25`；未混入工作目录中的其他网络调查改动。

## 使用方式与范围

启动器 Create profile → 命名 `1.8.9 (Clean Test)` → 选择 `1.8.9 · Clean Test` → Forge → 选择图标。使用新的 Profile ID，游戏目录为该 Profile 下的 `clean-test`。原有完整 Profile 继续使用 `unpvp-ui`，不迁移或覆盖其存档、设置。

保留原版标题、暂停、服务器列表和游戏界面。唯一的玩法附加功能为始终开启的自动疾跑与 Fullbright，无设置面板或快捷键。自动疾跑尊重食物、潜行、使用物品、碰撞及菜单焦点条件；Fullbright 只替换客户端光照贴图，不修改服务器光照。

保留 OptiFine HD U M5、Nothirium、EntityCulling、Phosphor legacy、FoamFix、RenderLib、ConfigurationsBackport、Patcher 性能子集，以及保留原版名字的模型遮挡剔除。Mac 保留原生 ARM Java 8、Retina 物理像素与鼠标坐标适配、OptiFine 窗口调整兼容处理。Windows 使用原有 Java 8 x64 路径。

不装入 `unpvp.jar`、`unpvp-pvp.jar`、`unpvp-network.jar`，因此不注册 Unbox 面板、HUD、名牌徽章、好友、私密邀请/中继、游戏内皮肤切换、Feedback 或网络诊断处理器。原版玩家名字和原版/OptiFine 皮肤行为仍存在。公开服务器仍需要有效的正版登录。

启动器在该游戏运行时暂停周期性好友同步，皮肤桥不向该游戏目录写入文件，退出不调用 Feedback 收集上传或私密世界恢复。启动之前已经发出的启动器请求可能仍完成；本次不是删除启动器账号功能。

## 实现位置

- `client-mod/src/clean-test/`：单独编译的两项功能、显示适配和模型剔除，无完整客户端依赖。
- `scripts/build-clean-test.py`：使用既有 1.8.9 编译缓存构建独立 JAR 与对应源码归档。
- `src-tauri/src/unpvp.rs`：按 `cleanTest` 分配模组集合、启动和退出路径。完整模式保持原行为。
- `src-tauri/src/main.rs`：独立目录及模式保存；只允许 Forge 1.8.9 Beta 的 Clean Test。
- `app/src/main.tsx`、`model.ts`：版本选择和 Profile 标签。
- `scripts/verify-beta-bundle.py`：旧引擎哈希、最小模块类路径和禁止网络/社交/Feedback 引用检查。

本次游戏启动验证发现组合加载时 ASM 可能先收到原始混淆名称。Clean Test Retina 适配通过 Forge 官方映射同时识别该名称和 SRG 名称；不修改完整 Profile 的既有 JAR。Mixin 最低版本与实际保留的 0.7.10 运行时对齐。
