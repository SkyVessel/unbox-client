# Discover 详情页与公开模组方案调研

日期：2026-10-23。分支：`codex/discover-project-details`。本轮包含启动器修复；游戏内模组架构、卡片样式、自制模组公开发布仅研究，没有实施。

## 已实现

- 左侧 Discover 默认不绑定 Profile，搜索全部 Modrinth 模组。Profile 的 Mods/Packs/Shaders “＋”继续锁定对应版本与加载器；手动选择 Compatibility 时仍可缩小范围。
- 再次点击侧栏 Discover 会回到全站浏览。详情页返回时保留搜索条件、分页与列表滚动位置。
- 删除客户端自设的一万条翻页限制。公开 API 实测 offset=10020 和 offset=50000 均正常返回项目，当前结果总数为 77561；此数值会变化。
- 新增 `catalog_project` 获取项目完整正文、图库、许可、版本、加载器、源码与问题链接，不依赖 Profile。
- 独立详情页：左侧作者介绍与截图，右侧选择安装 Profile、兼容检查、文件及依赖列表、大小、安装进度、取消和失败重试。无兼容文件不妨碍阅读介绍。
- 好友 Profile 继续只读；游戏运行期间可浏览但不能安装。安装成功可返回目标 Profile 查看文件。
- Markdown 与常见 HTML 经清理后渲染，保留标题、列表、表格、图片和折叠内容，不执行脚本、不嵌入 iframe、不接受页面事件处理器。任意作者自定义 CSS 不带入客户端。
- 正文解析相关代码仅进入详情页时加载，不增加主页的初始解析负担。

### 图片缺失原因

直接查询截图对应项目 `searchables` 和 `inventory-profiles-next`：两者 icon_url 均存在，gallery 均为空。没有作者封面时，旧卡片显示通用方块；现在使用该项目图标居中补位。真实封面优先；封面加载失败后用图标，图标也失败或缺失时显示名称首字母，不再直接隐藏图片留下空白。

未为网络波动增加代理、缓存服务或额外下载链路。项目正文里的图片使用作者的 HTTPS 地址，可显示独立于 gallery 的介绍图片。下载文件地址仍限定 Modrinth CDN，未放宽安装来源校验。

## 公开模组方案：结论

可以实现“Unbox 默认整合包 + 自有核心模块 + 模组设置入口”。不能对任意公开 JAR 自动提供可靠热开关，也不能仅凭 Modrinth 数据自动生成所有模组设置。

### 1. 下载客户端即可准备好模组

可行。启动器按明确的游戏版本、加载器、项目 ID、版本 ID 和文件哈希下载默认清单，复用缓存、依赖检查和失败回滚。首次启动前准备齐全，准备失败阻止启动并给出重试；断网且缓存齐全时可复用现有环境。用户添加模组不得覆盖默认包中已验证的同名模组和依赖。

可以额外提供 Unbox 的 `.mrpack`，其中有文件地址、哈希、依赖及客户端/服务端要求。此格式解决分发，不提供热加载或统一设置。依据：[Modrinth mrpack 格式](https://support.modrinth.com/en/articles/8802351-modrinth-modpack-format-mrpack)。

当前并非所有功能都是自制：`survival-mods-lock.json` 已直接使用大量 Modrinth 文件。Mouse Tweaks、ItemPhysic Lite、IPN、VeinMiner、FallingTree、Easy Shulker Boxes 等已有独立引擎和 Unbox 适配层。

例如 26.3 NeoForge 仍随包提供 Status Effect Bars、Resourcify、Colour Scroller 的移植版。表格描述现有锁定包，并未证明上游今天仍无新版。若要全部从 Modrinth 取得，需逐环境核对上游文件或先按许可公开自己的移植版，再重新验证；不能直接换成所有项目的最新版。

### 2. 热开关的实际边界

普通模组启动时会注册事件、快捷键、数据类型，部分会通过 Mixin 修改 Minecraft 或其他模组类。下载来源改变不会清除这些注册或注入。依据：[Fabric Loader 的模组与 Mixin 机制](https://docs.fabricmc.net/develop/loader/)。以下是基于该机制及本仓库适配代码的工程判断：

| 模组能力 | 游戏内开关方式 |
| --- | --- |
| 原生提供完整运行时启停接口 | 调用接口，检查输入、渲染、任务和临时状态是否一并停止 |
| 没有原生总开关，但我们已验证适配 | 用固定版本适配器在输入/渲染/事件入口拦截，并正确清理状态；JAR 保持加载 |
| 任意玩家安装、未验证的模组 | 不提供总开关；显示已加载状态，允许可用的设置入口 |
| 增加方块、实体、世界生成等内容 | 通常需要重启；不能用关闭开关卸载注册内容或删除已有世界数据 |

当前 `MouseTweaksGateMixin`、`BuildingKeyGateMixin` 等就是这种针对性适配。单改配置值并不能保证所有事件停止；必须保留以前“关闭后仍响应”的回归验证。关闭建筑模组不能再靠先打开界面再关掉。

对自制墓碑，即使关闭新死亡生成，也应保留已有墓碑的加载和取回物品能力。好友世界中的玩法开关以房主为准，访客只能修改本人的显示、输入等个人设置。

建议默认包只有经过启停验证的模块展示热开关；性能引擎和通用依赖不显示误导性即时开关。

### 3. 点击卡片进入模组自己的设置

可行，但通过模组提供的设置入口接入，不是从 Modrinth 描述里解析设置。

- Fabric：通过 Mod Menu 注册的 `getModConfigScreenFactory` / provided factories 打开对应原生 Screen，并传入 Unbox 列表作为返回页面。依据：[Mod Menu 配置 API](https://github.com/TerraformersMC/ModMenu#mod-config-screens)。
- NeoForge：优先使用 `IConfigScreenFactory`；按其注册的 config spec 可使用默认 `ConfigurationScreen`。它支持部分标准配置的自动生成，不能覆盖任意私有格式。依据：[NeoForge 配置页面](https://docs.neoforged.net/docs/misc/config/#configuration-screen)。
- 没有入口但配置结构标准且有明确元数据：可做专门适配。
- 没有设置页或只用自定义文件：显示“此模组未提供游戏内设置”，可链接作者文档。不要制造空设置页或猜测选项类型。

原生设置页面的样式由原作者控制；外层卡片可以统一。若要求每个设置页面也完全统一，则需要逐模组重做界面，维护成本明显增加。

现有 `ClientIntegrations` / `SurvivalClientMods` 会同步部分设置，个别选项会由 Unbox 覆盖。迁移到原生页面时必须明确配置归属，避免玩家修改后被同步代码恢复。建议以原生配置为数据源，Unbox 保留已声明的总开关、房主限制与必要的冲突处理；不能直接把所有同步代码删掉。

### 4. 自制模组上传 Modrinth

可行，但不是本轮执行项。地图、墓碑等若要成为独立项目，应拆出必要依赖、配置、数据迁移和加载器入口，保留原有方块/物品注册 ID 与存档结构，避免老世界损坏。不要为上传而强行将每一个 HUD 小组件拆成 JAR。

账号、资产、邀请、环境同步和统一菜单仍需要 Unbox 核心。可以让自制玩法模块依赖核心，但项目描述必须写明依赖和使用条件。

每个公开项目应包含真实功能说明、截图、图标、支持版本/加载器、依赖、许可和问题反馈入口。第三方移植保留原作者信息并说明修改，不当作原创。具体文件已在 Modrinth 上可用于 Modrinth 整合包；自行修改并重新发布仍需遵守该代码的许可。依据：[Modrinth 整合包许可说明](https://support.modrinth.com/en/articles/8797527-obtaining-modpack-permissions)。

### 5. 新的 Client Mods 卡片

视觉方案可行：正方形图标，下方叠加半透明开关条；从原作者图标取图，不改第三方品牌。模糊效果宜复用缓存或简单遮罩，避免每张卡片每帧做独立高成本模糊。保证开关文字与键盘焦点可见。

- 已验证可切换模块：图标区域进入设置，开关区域独立操作，事件不互相触发。
- 玩家安装的模块：同样展示图标、名称、版本；不显示总开关，有设置入口才可打开设置。
- 无设置项：明确状态，可进入说明，不伪装成可配置。
- 依赖库默认折叠或过滤，可在“全部”查看，避免 Fabric API 子模块等淹没玩家常用模组。
- 同一 mod ID 的内置与玩家安装记录合并识别，禁止重复卡片及重复 JAR。以加载器实际加载列表为准，不仅扫描目录。
- 从 Modrinth 安装时保存项目 ID/图标；手动导入时优先 JAR 元数据，可用文件哈希查询 Modrinth 匹配，不以显示名猜项目。
