# UDP 包大小、心跳与联机回退修复

2026-10-23，面向 0.2.20。发布状态见 [0.2.20 发布验证记录](71-0.2.20联机修复更新发布.md)。

## 修改

- VoxLink DATA 与 FEC 报文连同认证字段控制在 1200 UDP 字节以内；分块预算为 1174 字节，若启用 multiplex 则额外扣除通道字节。接收端仍能读取旧版报文，双方都更新才能保证双向发包预算。
- 心跳采用每侧每秒定时发送，不再收到心跳即回复，避免双方互相触发大量数据包。
- LAN 或 P2P 已选中后，加入期间出现 EOF、超时、通用断线或连接拒绝时，一次性切换到 e4mc 中继。已进世界后的掉线不自动重连；用户取消、过期邀请、权限拒绝、协议不兼容不执行回退。
- 中继连接重建私密登录 grant 和环境准备状态，重新验证身份和共享文件，复用缓存的完整文件。为旧异步同步任务增加代次检查，避免旧连接的失败覆盖新连接。
- 关闭确认窗口的异步回调不再被当作玩家主动取消；中继就绪的延迟回调核对邀请与代次，防止重复连接。
- 诊断记录增加断开原因的翻译键与 direct_connection_failed 阶段，不记录凭据或错误详情中的地址。
- Windows 构建流水线新增 Java 25 传输回归，对实际发布 JAR 内的网络类执行检查。

## 静默验证

- TCP / UDP 2 MiB 往返；错误密钥；超时进入回退；取消；丢包、乱序和重复包保序；全部通过。
- 模拟 1200-byte UDP payload 路径、60 ms RTT：256 KB 完整传输，DATA/FEC 均不超预算；12 秒空闲仅 24 个双向定时心跳，随后可继续传输。
- 两份隐藏 Fabric 26.1 游戏：在已认证的文件检查阶段切断 P2P，自动通过真实 e4mc 公网中继重新认证、入服并完成游戏事件。没有修改用户 Profile。
- 两份隐藏 NeoForge 26.3 游戏：相同故障后经中继下载 3 份共享文件（2,101,943 字节），重启后入服；模组物品、资源包、光影以及再次加入零下载/零重启通过。
- 局域网探测成功但游戏端口拒绝连接的隐藏双客户端测试通过，自动改用真实 e4mc 中继入服。
- Fabric 26.1.2 的界面和策略检查 36 项通过，包括取消、拒绝、协议错误以及中继可恢复的网络错误分类。
- 六套 Fabric / NeoForge 模块均编译并通过 bundle 预检。Windows 结果以发布流水线记录为准。

## 测试边界

游戏验收使用同一 Mac 上的独立本地测试账号；P2P 由回环 NAT 夹具建立，中继为真实 e4mc 公网服务。没有宣称已经完成 Windows 房主/macOS 访客的异地实玩或公网 NAT 穿透率验证。信令使用本地 Worker 测试实例，本轮无需更改生产 Worker。
