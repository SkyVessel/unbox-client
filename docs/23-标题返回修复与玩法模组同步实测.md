# 标题返回修复与玩法模组同步实测

2026-10-10；Minecraft 26.1；本地 macOS 0.2.5 调试包。没有发布 Release 或部署 Cloudflare。

## 标题页返回

原逻辑只在 `Minecraft.setScreen` 的 HEAD 替换显式传入的 `TitleScreen`。部分页面的 Esc 返回调用 `setScreen(null)`；在没有世界加载时，原版在方法内部构造新的 `TitleScreen`，因此绕过入口替换。

保留入口处理，另在该方法写入屏幕局部变量时进行相同检查，只替换原版 `TitleScreen`；保留 Demo 检查，不用逐帧轮询补救，不改动世界内空屏幕、死亡或聊天屏幕的处理。

扩展 `HomeSmokeTest`，用实际 Escape 按键调用代替直接 `onClose()`，覆盖世界选择、多人入口、游戏设置、皮肤设置；补充无父页面 Esc 返回及显式请求原版标题页。

- 修复前：Fabric 在新增的无父页面 Esc 断言失败，确认回归测试能复现问题。
- 修复后：Fabric、NeoForge 各 25 项标题页检查通过，含小窗口及 GUI 缩放检查。

## 玩法模组测试

采用独立测试玩法模组 **Shared Gameplay Fixture**（`unbox_sync_fixture`），不是 Client Mod。它注册一个新物品：使用后由服务端将手中物品兑换为绿宝石。Fabric 和 NeoForge 各用原生注册入口，共用该物品代码。源码在 `tests/fixtures/`，每次从源码编译，仅放入房主的隔离测试 Profile；JAR 添加约 2 MiB 测试数据以覆盖分块传输。

使用两个真实游戏进程及房主集成服务器，好友账号来自本地 Cloudflare 兼容测试服务。测试程序调用正常邀请、加密登录、模组传输及 Rust 共享 Profile 创建逻辑；由测试脚本驱动访客进程重启。世界均为复制件，不修改用户原世界或真实云端账号。

| 检查 | Fabric | NeoForge |
| --- | --- | --- |
| 只有房主预装玩法 JAR，访客初始没有该 JAR | 通过 | 通过 |
| 共享清单只有玩法模组，不包含 Unbox/托管性能模组 | 1 项 | 1 项 |
| 首次下载字节数 | 2,100,749 | 2,100,868 |
| 原生启动器校验缓存并创建独立好友 Profile | 通过 | 通过 |
| 重启后加入房主世界，访客注册新增物品 | 通过 | 通过 |
| 房主使用物品，获得服务端奖励 | 通过 | 通过 |
| 访客发出真实物品使用数据包，服务端执行并同步背包 | 通过 | 通过 |
| 房主服务器确认访客奖励 | 通过 | 通过 |
| 退出再加入同一世界 | 通过 | 通过 |
| 再次加入下载量 / 是否再次重启 | 0 字节 / 否 | 0 字节 / 否 |
| 再次加入仍保留模组使用奖励 | 通过 | 通过 |

两组均有 8 项房主检查、7 项访客检查通过，另外验证同名不同 UUID、拒绝错误邀请和房主身份冒用、死亡标记及访客权限。首次访客下载完主动退出是重启流程的一部分，不是崩溃。

这证明了本机局域网条件下，两种加载器各自的“仅房主安装 → 访客同步 → 重启加入 → 实际使用 → 零下载重连”链路。没有测试跨加载器转换，也不能据此宣称大型第三方整合包、完整 config/脚本同步、两个异地家庭网络或正版双账号都通过。本轮没有发现需要更改同步生产逻辑的问题。
