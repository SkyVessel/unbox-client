## 1. 接手结论

已把本会话的 Pen 界面嵌入 **Minecraft 26.3 / Fabric** 与 **1.8.9 / Forge**，验证了两个原生版本中的画面、页面切换、缩放和世界内开关界面的表现。

这是独立的 UI 展示实验。它没有替换正式 Unbox 模块，没有接入真实好友、账号、皮肤或模组服务，没有发布 GitHub Release，也没有修改更新渠道。不能把本轮测试包当成正式客户端功能已经迁移完毕。

渲染方案是 **SVG 矢量路径 → Java2D 按物理像素抗锯齿绘制 → 游戏纹理缓存**。稳定帧绘制一张缓存表面，不每帧解析 SVG 或重新生成界面。它不是每帧由 GPU 直接细分矢量路径的渲染器。

本机对照未观察到关闭 UI 后的持续帧时间退化。打开完全不透明的菜单时跳过不可见的世界绘制，减少了开销。切页、首开和改尺寸仍有一次性生成及上传成本；没有“所有硬件零开销”的结论。

### 必须保留的实现细节

- 缓存分辨率使用物理帧缓冲尺寸，不用整数 GUI 尺寸生成低分辨率画面再放大。
- 1.8.9 的投影可带小数，而 `GuiScreen.height` 向上取整；最终绘制使用 `1 / ScaledResolution.getScaleFactor()` 的物理像素映射。1686×958 / GUI Scale 3 的约 2 像素拉伸问题已据此修复。
- 改尺寸期间旧缓存居中按 1:1 像素显示，等待匹配尺寸的结果；不拉伸旧缓存。
- 形状裁切与内容图片遮罩需要保留抗锯齿，不能仅依赖硬裁切边界。
- 页面切换复用当前 Screen；离开 Screen 时释放游戏纹理并关闭绘制 worker。
- 当前世界绘制跳过条件是 `screen instanceof PreviewScreen`，因为本实验全部不透明。它没有读取实际透明度值，后续加入透明、淡入淡出或其他露出世界的状态时必须修改此条件。
- 1.8.9 的菜单限帧策略仅在 PreviewScreen 中生效；世界正常绘制路径保留原配置。对比菜单性能时应区分原版菜单上限与本实验上限。

## 5. 构建与运行

以下命令在项目根目录执行。交接本身未重新运行游戏或重建 JAR。

### 本机依赖

- `java`、`javac`、`jar`：当前构建使用 JDK 25；旧版通过 `--release 8` 编译。
- Python 3；像素比较脚本另需 Pillow，本机已有 `.cache/pvp-build-venv/bin/python`。
- 现代版：`.cache/client-26.3.jar`、`.cache/runtime-26.3/` 中的版本元数据、Fabric 元数据、libraries 和 assets。
- 旧版构建：`.cache/unpvp-build/` 中的 named Minecraft/Forge JAR、libraries、SpecialSource 和 `named-srg.srg`。
- 旧版运行：`.cache/unpvp-runtime/`；`.cache/unpvp-launcher-check/runtime/` 中的 Java 8 与 assets；`src-tauri/resources/unpvp-runtime.json`。

目前启动脚本按本机 macOS 的库、原生运行库和 Java 路径组织。它不是跨平台安装器，也不会自动准备全部依赖。迁移新机器先检查上述输入；不要把缺失缓存当作 UI 源码错误。

### 普通构建

```sh
python3 scripts/build-vector-preview.py
```

输出在 `outputs/vector-ui-preview/`：

- `unbox-vector-26.3.jar`：Fabric 原生模块。
- `unbox-vector-1.8.9.jar`：完成 SRG 重映射的 Forge 原生模块。
- `unbox-vector-1.8.9-named.jar`：编译中间产物，正常启动使用前一个 JAR。
- `Open-26.3.command` / `Open-1.8.9.command`：本机双击入口。

现有场景资源足够直接构建。**只有设计变化并重新导出 SVG 时**才执行：

```sh
python3 scripts/prepare-vector-preview.py
```

该脚本有本机 Pen `assets` 绝对路径，通过图片哈希识别并替换品牌素材。迁移机器时先修正路径或迁移对应素材；缺少该目录可能导致品牌矢量替换没有发生，不能仅凭脚本输出“Packaged”判断素材正确。

### 手动预览

```sh
python3 scripts/run-vector-preview.py 26.3 --manual --width 960 --height 540
python3 scripts/run-vector-preview.py 1.8.9 --manual --width 1440 --height 810
```

每次创建 `.cache/vector-preview/runs/<name>/`，复制测试 JAR，使用虚拟离线身份和独立 options / saves。`--manual` 打印子进程 PID 后返回，游戏继续运行。日志在该目录的 `launch.log`。macOS 高分屏的窗口尺寸与物理帧缓冲尺寸可能不同，以日志和截图尺寸为准。

| `modern-resize` | 26.3 菜单、输入与窗口 / GUI Scale 变更 |

| `modern-world-final` | 现代版最终世界内对照 |

两版各有 14 张游戏 UI 截图与本次物理尺寸的矢量表面 RGB 逐像素一致，共 28 张；菜单流程还各含前后两个纯色 baseline。共用代码检查覆盖全部 16 个场景，不能把它描述成两版各做了 16 张原生 UI 截图比较。

逐像素比较的对象是“游戏截图”和“运行时生成的矢量表面”，用于检测呈现过程中的缩放、裁切和颜色偏差。它不等于 Pen PNG 与游戏逐像素相同，也不等于 Java 8 与 Java 25 两套栅格化结果已经彼此逐像素一致。设计几何与文字路径来自同一份 Pen SVG。

输入检查调用原生 Screen 的鼠标、键盘回调，验证坐标映射和焦点；没有逐一覆盖操作系统级输入设备、所有按键组合及无障碍流程。

### 可复现命令

运行名必须全新；以下示例会打开实际游戏窗口。依次运行以避免测试进程互相争用资源。

```sh
javac --release 8 -cp .cache/vector-preview/forge189 -d .cache/vector-preview/test tests/vector-preview/VectorPreviewTest.java
java -Djava.awt.headless=true -cp .cache/vector-preview/test:.cache/vector-preview/forge189 dev.unbox.preview.VectorPreviewTest

```

不要给真实旧版游戏启动照搬单元测试中的 `-Djava.awt.headless=true`。早期一次旧版启动在 macOS / LWJGL 原生窗口层崩溃，后续正常参数运行通过；未据此证明旧原生运行库在所有环境下稳定。

`run-vector-preview.py` 默认是自动检查模式，最长等待 180 秒；手动检查须加 `--manual`。检查模式由 `unbox.vectorTest`、`unbox.vectorWorld`、`unbox.vectorResize` 三个 JVM 属性控制。

`verify-vector-preview.py` 收集像素结果、CSV、截图和哈希。它记录运行 JAR 与输出 JAR 的内容哈希；要确认具体证据对应交付包，还应比较各运行 `jarContentSha256` 与 `build-hashes.json` 的 `contentSha256`。原始 ZIP 哈希受时间戳影响，不能仅用 ZIP 哈希不同推断代码不同。最终四次运行已经做过内容哈希相等检查。

详细数据见 [86 号报告](86-游戏内矢量UI双版本原型验证.md)。关键数值：

| 指标 | 1.8.9 | 26.3 |
| --- | --- | --- |
| 稳定菜单 UI CPU 提交中位数范围 | 0.087–0.120 ms | 0.003–0.019 ms |
| 世界帧时间中位数：打开前 → 最后关闭后 | 5.422 → 5.334 ms | 4.689 → 3.849 ms |
| 世界帧时间 P95：打开前 → 最后关闭后 | 7.816 → 7.920 ms | 8.292 → 7.765 ms |

## 7. 后续正式接入前需要处理的事项

本节是接手建议，未在本轮继续实施。

1. **先确定正式入口。** 把共用绘制能力接入现有生产 Screen / 加载器适配层；处理标题、按键、世界绘制和限帧 Hook 的冲突。不要直接同时安装实验和正式模块。
2. **把静态场景拆成动态组件。** 当前文字已转轮廓、热点坐标手写，只适合已知状态展示。真实好友列表、昵称、输入框、滚动、搜索和实时状态需要动态文字、布局与命中区域，不能靠整页 SVG 穷举状态。
3. **处理实时人物与资产。** 接入真正的玩家模型、皮肤、资产状态及保存 / 失败反馈；保留已有账号权限与业务边界。
4. **明确透明度策略。** 当前滑块没有功能。实现透明度后，应只在真正完全遮住世界时跳过世界绘制；透明或过渡状态必须恢复世界画面。
5. **评估首开与切页延迟。** 评估局部重绘、组件缓存或预热是否有必要；同时复查快速切页、关闭与改尺寸时的任务取消、缓存线程安全和内存占用。当前只测了稳定态及有限窗口变化。
6. **扩展验证范围。** Windows/Linux、其他硬件、高分屏 / 全屏、GUI Scale 各档、长时间开关菜单、实际整合包和第三方渲染模组组合仍待验证。需要另测首开 / 切页长帧与 GPU 开销。
7. **评估素材分发。** 第三方服务器图和示例皮肤是设计内容素材，本地实验使用不自动代表已取得产品分发授权。

`VectorScene` 只支持本次导出使用的 SVG 子集，例如 M/L/H/V/Q/C/Z 路径、基本形状、矩阵/平移/缩放、裁切及嵌入图片。不要将它当通用 SVG 引擎；新导出如出现其他命令、渐变或效果，应先验证支持范围。
