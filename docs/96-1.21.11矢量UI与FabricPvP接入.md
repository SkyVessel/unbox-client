## 2. 分类、真实功能与默认值

1.21.11 Fabric 的 Survival 与 PvP 共享 FPS、CPS、Latency、Keystrokes、Armor Status、Auto Sprint、Zoom、Crosshair、Chat、Scoreboard、Coordinates、Viewmodel、Daytime。两页显示各自卡片，读写同一个模块 ID、配置键与运行实现。PvP 不展示 VeinMiner 等生存模块；外部 PvP 项目不混入 Survival。

`PvpModules` 的 Fabric 实现在 `client-mod/src/1.21.11/fabric/java/`；其他组合使用无 PvP 的 stub。新增卡片来自 `client-mod/pvp-lock-1.21.11-fabric.json`，锁定发行文件、依赖、哈希和来源。

- 16 个主项目全部有条目，其中 14 个新安装时默认启用；Natural Motion Blur、TweakHands 默认关闭。模糊效果不承担输入平滑或卡顿修复。
- 原生 Viewmodel、Daytime 默认开启，Viewmodel 默认变换为原尺寸/原位置。新配置还默认启用常用共享 HUD；保留用户已有开关值。
- Unbox 原生 Crosshair 默认关闭，优先使用 Crosshair Addons。Better Hitreg 的重复碰撞箱、准星、距离及跳跃提示默认关闭，只在没有配置文件时写入这些默认值。
- TweakHands 保留为可选方案。启用其 JAR 时关闭原生 Viewmodel；TweakHands 已加载期间，原生 Viewmodel 的可用性策略继续阻止双重变换。
- Shulker Box Tooltip 加载时，关闭 EasyShulkerBoxes 的重复内容预览，保留其物品交互。
- BactroMod 3.5 实际没有清单中描述的物品缩放/小图腾设置。物品缩放由原生 Viewmodel 提供；小图腾由 Better Totem Counter 的 `popAnimationScale` 提供，新文件默认 0.5，不改写已有文件。不能声称这些功能来自 BactroMod。

公共 JAR 的启停需要重启。卡片与详情页区分 `Loaded`、`Disabled`、`Restart required`、`Not installed`；切换时验证 SHA-512 后重命名 `.jar` / `.jar.disabled`，不覆盖不同版本或改过的文件，也不冒充热卸载。运行中的 loaded 状态和下次启动状态分别读取。

上述设置入口已由用户后续要求覆盖：16 个 PvP 模组卡片全部直接进入 Unbox 设置页，读写原模组配置；不再通过 `Configure` 转到作者的界面。实现、配置覆盖与检查边界见 [97 统一设置面板](97-1.21.11PvP统一设置面板.md)。

Theone’s Eating Animation Pack 是可选资源包，卡片提供作者下载页与资源包管理入口。其素材没有下载并打包进 Unbox，`Optional resource pack` 不代表已经安装。

## 3. 原生 Viewmodel 与 Daytime

- `ViewmodelMixin` 在 1.21.11 `ItemInHandRenderer.renderArmWithItem` 的手部 PoseStack 作用域内变换。支持 XYZ 位移、25–150% 缩放、三个旋转轴；空手和副手可分别设置。设置页绑定真实配置，默认数值保持原样。不会更改玩家位置、相机输入、攻击/挥手时序或发送旋转包。
- `DaytimeMixin` 只覆盖客户端 Level 的可视 day time，保留完整天数/月相周期，替换一天内的 tick。默认 6000，可调 0–23999；不修改服务器世界时间，不发送时间命令。
- 两者仅在 1.21.11 Fabric 接入，本轮没有给 26.3 添加 PvP 功能。
- 按用户要求，没有操作游戏视角。世界内手部显示、回头动作、天空变化和服务器实战效果仍待用户验收；编译、菜单设置及 Mixin 启动不等同于这些体验已通过。

## 4. Look Behind 的兼容性修复

作者公开 1.0.2 文件声明支持 1.21.11，但实际 Camera Mixin 仍引用旧的 BlockView/BlockGetter setup 签名，启动时失败。

在 `ports/look-behind-1.21.11/` 根据作者公开源码制作原生适配，使用正确的 `Camera.setup(Level, Entity, boolean, boolean, float)`。保留 GPL-3.0-or-later 许可与 `UPSTREAM.json` 中的来源 commit，改后源码随 JAR 的 `META-INF/unbox-source` 提供。锁文件同时保存原发行物信息与本地构建哈希。

另移除了原实现每 tick 强制写 HUD 隐藏状态的行为；菜单、失焦、没有玩家时清理按住状态。R 默认键可在 Controls 修改。不能同时安装原版与本地适配版。已验证启动和 Mixin 兼容性，没有测试回头视角体验。

## 5. 动画与延迟

共享 `UiTransition` / `UiTransitionMixin` 在原生切页时复制上一帧 GPU 纹理，目标页可绘制后做 **120ms smoothstep 淡出旧帧**，露出新页。操作与目标 Screen 的切换立即执行，不用等待动画结束再执行导航，不使用 sleep。

目标页首次生成期间保留旧画面，避免空白闪烁。此期间新页控件只在匹配表面就绪后接收输入，避免画面与点击位置错位；这不是“所有首次加载都为零耗时”的承诺。

- `SolidSurface` 增加按内容寻址的 CPU LRU 缓存，预算 128MiB。
- `SolidScreen` 增加图像身份对应的 GPU LRU 缓存，预算 128MiB；当前活跃纹理不被强制逐出，活跃工作集可能超过预算。关闭页面释放引用，空闲项可逐出。
- 缓存键包括场景、物理尺寸、GUI 密度、绘制操作和卡片条带内容。不能仅按页名缓存，不能返回上一个主题/尺寸/状态的图片。
- 主菜单空闲时预热快捷菜单和 Mods；离开主菜单或进入世界时取消未完成预热。不在世界游玩时持续绘制隐藏 UI。
- 删除设置页原有的第二段入口位移/透明度动画，直接构造目标设置内容，避免先显示列表再跳详情。
- Survival / PvP 保持同一面板与卡片位置，用 120ms 图集过渡；滚动仍有明确首尾边界。
- 初次标题不捕获加载启动画面；缩放/窗口尺寸变化、减动画设置和目标页改变会清理过期过渡。
- Java2D 使用 `-Djava.awt.headless=true` 离屏绘图；在 macOS NeoForge 的早期窗口/AppKit 路径下，不设置该标志曾卡住矢量 worker。已加入对应测试启动及启动器 26.3 / 1.21.11 JVM 参数。

日志中的 `ready-ms` 测量 setScreen 到目标可绘制，包含该轮调度；不是点击到显示器的端到端延迟，也不是 FPS 指标。本轮 26.3 一次回归中重新打开 Mods 约 1–2ms，首次皮肤页约 74–79ms；不同机器、尺寸和首次字体初始化仍会变化。没有在本轮进行 FPS/启动速度的受控性能对照，不报告性能提升百分比。

## 6. HUD 背景

1.21.11 与 26.3 的共享 HUD 默认背景改为关闭；设置页 fallback 与渲染 fallback 必须一致。包括一般背景开关、Keystrokes 背景透明度/边框、Chat 背景、Scoreboard 标题/正文背景，以及效果条背景。玩家显式保存的值保留，仍可在相应设置中重新开启。

Shield Cooldown HUD 的固定灰色底板通过 `PvpHudBackgroundMixin` 的两个 fill 颜色参数变透明，保留图标和冷却条。其 Unbox 详情页提供 `HUD background` 开关，默认 Off。该 Mixin 仅匹配锁定外部版本；升级时必须重新核对目标，不可盲目沿用。

## 7. 构建与复现

在项目根目录运行：

```sh
# 独立原生模块；Gradle 驱动使用本机已有 JDK，目标游戏使用 Java 21
./client-mod/gradlew -p ports/look-behind-1.21.11 build
./client-mod/gradlew -p client-mod -Pminecraft=1.21.11 build
./client-mod/gradlew -p client-mod/neoforge -Pminecraft=1.21.11 build

# 26.3 脚本读取环境变量，不读取位置参数
UNBOX_MINECRAFT_VERSION=26.3 sh scripts/build-mod.sh
UNBOX_MINECRAFT_VERSION=26.3 python3 scripts/build-neoforge-mod.py

# PvP 准备仅用于明确指定的 1.21.11 Fabric 游戏目录
python3 scripts/prepare-pvp-mods.py /absolute/path/to/isolated-game

# 隔离、无世界操作的 Fabric 检查
python3 scripts/test-backport-fabric.py 1.21.11 --java /absolute/path/to/java21 --smoke portUi --pvp

# 同脚本加 --interactive 打开独立手动测试 Profile，不自动进入世界
python3 scripts/test-backport-fabric.py 1.21.11 --java /absolute/path/to/java21 --pvp --interactive
```

依赖前置准备沿用 73 号文档和 `prepare-backport-runtime.py`。第三方 JAR 按锁定 URL/哈希下载，原生 Look Behind 从锁文件的 `localArtifact` 读取；重新构建后若字节变化，需核对并更新哈希。保留已有 `.disabled`、用户配置和修改过的 JAR。不能把测试目录复制覆盖用户游戏目录。

输出位于 `client-mod/build/fabric-1.21.11/libs/`、`client-mod/build/neoforge-1.21.11/libs/` 与 `src-tauri/resources/*26.3.jar`。启动器版本选择仍沿用当前已开放版本；本轮没有把整个旧版移植项目标成全面验收完成。1.21.11 使用上面的隔离入口测试，不能宣称已经通过正式 Launch 面板交付。
