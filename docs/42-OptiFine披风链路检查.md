# OptiFine 披风链路检查

2026-10-18。本轮按用户“先看看模组有没有问题”检查；没有修改产品代码、账号设置或发布版本，没有启动游戏。

## 已确认的问题

1. 下载入口：`OptifineCape.java:21` 仅请求 `https://s.optifine.net/capes/<游戏名>.png`。在本机使用与模组相同的 Java HttpClient 参数，对公开参考账号 sp614x 请求，HTTPS 返回 `SSLHandshakeException: Remote host terminated the handshake`；HTTP 同一路径返回 200、1562 字节有效 PNG（92×44）。Python 无代理请求交叉验证结果一致。该证据证明当前本机下载路径失败，不证明所有网络永久不支持 HTTPS，也不追溯断言之前试玩的唯一原因。
2. 失败永久缓存：任何请求错误、非 200 或解码错误均将 future 完成为空，没有过期、重试或清除路径。直接调用现有 Fabric 26.1 生产 JAR 的方法，失败后的第二次调用仍使用同一已完成空结果，复现成功。
3. 64 人硬上限：缓存记录包含没有披风和请求失败的名字，达到 64 后所有新名字都不再请求，且换世界没有清理。对同一生产类用进程内测试数据填入 64 条失败记录，确认新名字不会进入请求队列。测试仅运行于独立 JVM。
4. 错误完全静默：上述失败没有日志或 UI 区分，无法判断没有披风还是下载失败。

## 需要修复时一并验证的兼容风险

`LocalSkin.replace` 返回缓存的完整 PlayerSkin，其中 cape/elytra 是首次加载本地皮肤时的快照；LocalSkinMixin 与 CapeMixin 都在 getSkin 的 RETURN 处可取消注入。需要统一组合本地皮肤与最新披风，验证两种下载先后顺序和开关行为。本轮未启动游戏，未将该风险认定为已复现的渲染故障。

## 已核对正常的部分

- 六个资源 JAR（26.1 / 26.1.2 / 26.3 × Fabric / NeoForge）均有披风代码及 CapeMixin 注册，OptifineCape 类字节哈希相同，没有版本漏装。
- 原版 26.1 和 26.3 AvatarRenderer 仍从 getSkin 提取披风，CapeLayer 仍读取 cape.texturePath；没有发现这两个端点版本的渲染接口失配。
- 披风属于本地视觉功能，不要求房主安装，普通服务器策略没有封禁它。
- 查询使用真实游戏 GameProfile 名称，不使用本地 nickname 显示名。OptiFine 披风按 Minecraft 用户名关联；官网说明：https://www.optifine.net/capeChange 。
- 当前规则是官方披风优先；模组默认关闭，原版 Skin Customization 的 Cape 开关同样控制可见性，穿鞘翅时原版不渲染背部披风。这些是现有设计条件。

## 验证范围

临时复现程序和结果位于 `.cache/cape-audit/`。本轮未使用用户账号或登录凭据，未为当前账号添加他人的披风；公开 PNG 只用于网络响应和尺寸检查。没有进行有披风账号的游戏展示测试。此前通用 benchmark 明确设置 `cape=false`，不能以此前的 68 项通过证明披风端到端可用。

## 建议修复顺序

先处理可达的下载入口并保留大小、PNG 尺寸校验和超时限制；再区分“没有披风”和临时失败，增加有限重试及可淘汰缓存，去除全会话 64 人硬阻断；统一皮肤/披风组合，并补真实渲染与失败恢复测试。HTTP 为未加密传输，若采用该来源，应明确限定为公开披风图片，不携带账号凭据，不能通过关闭 TLS 证书校验解决。

## 2026-10-19 修复实现（按要求不运行测试）

- 下载使用此前检查确认可达的 OptiFine HTTP 图片路径。只请求公开披风，不携带登录凭据、不跟随重定向；保留尺寸和文件大小限制，增加 PNG 签名/IHDR 检查及响应体读取超时。
- 将临时网络/解码失败与 HTTP 404 分开处理：失败 30 秒后可重试，无披风 5 分钟后可重查；重试仅在玩家仍需绘制披风时触发。失败写入日志。
- 删除全会话 64 人硬上限。每隔 600 个客户端 tick 清理超过 5 分钟未使用的已完成条目；切换世界、离开世界或关闭功能时释放缓存纹理。旧世界的异步结果不会重新注册。
- 本地皮肤与披风合并到一个 getSkin 注入入口，删除原独立 LocalSkinMixin；本地皮肤仅缓存身体纹理/模型，保留每次读取到的最新官方披风和鞘翅信息。官方披风仍优先，“仅本人”设置仍有效。
- 披风画布按 2:1 比例同时扩展宽高，避免独立取整导致纹理比例错误；纹理 ID 区分名字大小写，避免两条缓存记录共享并误释放同一纹理。

用户要求无需测试，本轮不运行自动测试、网络复测或游戏实测。构建状态见 `.cache/cape-fix/`；编译和打包成功不表示真实披风展示已经验证。未发布 GitHub 更新。
