# 26.3 启动链路与帧时间优化

日期：2026-11-12。用户关闭其他游戏后，继续授权独立世界、固定视角性能对照；不使用用户存档、不操作游戏视角。

## 基线与方法

- 本轮基线为上一轮交付的 26.3 构建，保存在 `.cache/ui-performance/round2-baseline/`。与第 92 篇中存在其他游戏干扰的诊断数据分开。
- 游戏测试每场景预热 8 秒、记录 15 秒：主菜单、世界、快捷菜单、Mods 静止、Mods 滚动、Minimap 设置。相同种子世界副本、出生点、2560×1440 framebuffer、GUI Scale 2、渲染 12 / 模拟 8、无垂直同步、4 GiB 内存。
- 原版 `maxFps=260` 为 Unlimited：已核对 `Minecraft.renderFrame` 在值小于 260 时才调用限帧器。主菜单保留原版 60 FPS 限制。
- `r2-base-fabric-1` 启用 JFR，只用于定位热点。正式对照优先使用未启用 JFR 的重复运行。
- `scripts/benchmark-launcher.py` 在 `.cache/launcher-performance/` 生成一次性启动器源码副本，自动点击真实前端 Launch 按钮，记录点击时间、原生命令接收时间、准备阶段和主菜单可用时间。测试覆盖实际库/资源校验、加载器、性能与生存依赖准备；测试账号绕过真实账号认证，不读取账号凭据。
- 启动测试的统计对象是资源已就绪后的重复启动，不包含首次下载或账号网络认证。首次准备单独标记，不混入结果。测试注入只在临时源码/临时客户端 JAR 中，交付包不含此次注入。

## 已定位开销

JFR 的主线程样本中，GUI `hasIntersection` / 层级查找、地图 tile 查找和部分配置读取有可见开销。最终优化：明确 Mods 列表与 HUD 的绘制层级；模块开关使用两个复用矢量蒙版替代 14 个分片提交；地图连续取色复用最近一个已加载 tile，保留变更、磁盘合并和淘汰规则。

## 启动器优化

- 本地调试包将 SHA-1 / SHA-512 库设为优化编译，启动器自身保留调试信息。每个资源的哈希校验仍执行；本项收益主要针对此前交付的本地 debug 应用，release 原本已优化，不能套用相同提升比例。
- 生存模组首次校验后记录已安装且正确的条目。此类条目不重复准备下载缓存；打包资源仍验证，安装阶段仍复核目标文件，修改或冲突文件继续保留并报错。
- 自有客户端 JAR 内容相同时不重写文件，保持加载器缓存使用的文件元数据稳定。
- 15 项 launcher Rust 测试通过，新增已校验安装在缓存缺失/离线时仍可使用、篡改拒绝、未变 JAR 元数据保留的回归。
- 26.3 地图缓存通过热点更新/淘汰、9792 个可见 tile、待写数据淘汰恢复、磁盘错误重试、跨世界重开与损坏目标恢复测试。

最终构建重复启动结果（毫秒；实际 Launch 按钮 → 原版加载层消失且 Unbox 主菜单表面可用）：

| 加载器 | 旧版两次 | 最终新版两次 | 均值变化 |
| --- | --- | --- | --- |
| Fabric | 35202 / 34979 | 13803 / 12818 | 35.09 → 13.31 秒，约缩短 62% |
| NeoForge | 39278 / 38857 | 13820 / 13652 | 39.07 → 13.74 秒，约缩短 65% |

旧版 Java 启动前准备约 23.2–26.0 秒，新版约 0.97–1.85 秒；Java 初始化本身约 11.8–12.8 秒。此结果来自缓存资源、测试身份、本机调试版，每组合两次，不能外推为首次下载、真实认证或 release 的同等提升。每加载器首次准备运行单独保留，不计入重复启动均值。

## 候选模组

ModernFix 的首轮固定视角对照没有显示明确 FPS 收益，未默认加入。More Culling 对应 26.3 的 1.9.1 为 release，1.9.2 为 beta；本轮选 release 进行独立评估，原始 API 元数据与 SHA-512 校验保留。来源：[作者页面](https://modrinth.com/mod/moreculling)、[源码与说明](https://github.com/FxMorin/MoreCulling)。不将候选源码合入客户端。

## 迭代与验证边界

首版将显式绘制层级用于所有矢量菜单，Mods 的 FPS 提升，但两次快捷菜单结果略低。最终把此处理收窄到 `VectorModsScreen`，保留快捷菜单原路径；模块开关两个蒙版及 tile 热点缓存保留。`r2-after-fabric-1/2` 是此首版的诊断，最终交付以 `r2-full-after-*` 为准。

最终构建完整默认模组集对照如下。两侧均移除 Dynamic FPS，避免窗口焦点触发后台限帧；其他依赖相同。每格是一轮 15 秒采样，不能视为统计显著结论。

| 场景 | Fabric 旧 → 新 FPS | NeoForge 旧 → 新 FPS |
| --- | --- | --- |
| 固定视角世界 | 231.2 → 224.6 | 237.3 → 228.7 |
| 快捷菜单 | 254.1 → 262.2 | 251.8 → 256.6 |
| Mods 列表 | 209.0 → 243.3 | 217.0 → 246.5 |
| Mods 平滑滚动 | 212.8 → 254.7 | 213.8 → 244.7 |
| Minimap 设置 | 215.3 → 217.3 | 215.5 → 210.6 |

Mods 平均 FPS 约提高 14–16%，滚动约提高 14–20%。Fabric 的 Mods / 滚动 p99 帧时间约从 9.9ms 降到 8.3 / 8.0ms；NeoForge 对应 p99 从 8.57 / 8.14ms 变成 8.81 / 8.94ms，尚未证明慢帧改善。普通世界平均 FPS 在这两对样本中低约 3%，其他轮次波动，未证实稳定提升，也未排除小幅回退。测试期间观察到系统存储管理等后台任务，保留所有轮次，不用峰值代替结论。

地图 10240 次取色微测约由 Fabric 1.68ms → 1.41ms、NeoForge 1.77ms → 1.53ms，颜色 SHA-256 一致。这证明局部热点减轻，不代表整体世界 FPS 同比例提升。进入相同已生成世界约 Fabric 2.34 → 2.43 秒、NeoForge 2.70 → 2.85 秒，本轮没有进入世界加速证据。

More Culling 1.9.1 世界独立对照：Fabric 232.9 → 224.1 FPS，NeoForge 226.3 → 223.1 FPS；p99 分别 8.50 → 8.30ms、8.25 → 9.27ms。两侧启动及进入世界正常，但未测出足够收益，未加入默认锁文件或交付包。ModernFix 同样保留在独立测试目录。

最终 UI 原生检查每加载器 34 项通过；367 项矢量/几何与 318 项布局检查、5 项版本源码隔离检查通过。普通菜单人工截图检查限布局与开关，不操作游戏视角。
