# 0.2.23 独立 Beta Profile 发布

## 授权与范围

用户于 2026-11-14 明确要求将新版 26.3、1.21.11 和第 102 篇中的 1.8.9 发布给同事、测试员，提供 macOS ARM64 / Windows x64，并明确标注 Beta。现有同版本 Profile 不得自动使用 Beta 内容。

本次启动器版本为 0.2.23。新建 Profile 时可选择：

| 选项 | 加载器 | 内容 |
| --- | --- | --- |
| 26.3 · New UI Beta | Fabric / NeoForge | 新矢量 UI、两主题、响应式布局、平滑有界滚动 |
| 1.21.11 · PvP Beta | Fabric | 新 UI、PvP 卡片及 Unbox 统一设置、Viewmodel / Daytime |
| 1.8.9 · unpvp Beta | Forge | 第 102 篇独立客户端及固定性能包 |

26.3 Classic、26.1.2、26.1 保持原有入口。1.21.11 NeoForge、1.20.1 不在本次 Beta 发布范围。新建、Profile 切换和 Launch 按钮均标注 Beta。

## 隔离与启动

- Profile 保存 `channel: beta`；缺失字段按 stable 处理。保存启动器状态时，以磁盘 Profile 的 channel 为准。
- 六个 stable 客户端 JAR 从公开 v0.2.22 获取，逐字节 SHA-256 校验，继续使用原资源名。Beta 使用独立资源名，构建脚本也不再覆盖 stable 26.3 JAR。
- 校验清单为 `src-tauri/resources/beta-release-integrity.json`，检查入口为 `scripts/verify-beta-bundle.py`。
- Beta 不自动挂接 stable 共享世界/资源库。1.8.9 实际游戏目录为对应 Profile 下的 `unpvp-ui`，桥接状态、皮肤和邀请恢复使用此目录。
- 好友 Profile 的固定 UUID 命名空间包含 Beta channel。相同房主的 26.3 Classic / Beta 不复用目录；普通旧 Profile 和存档保持不变。
- 1.21.11 Fabric 的公开依赖及两个原生移植由 `beta-mods-1.21.11.json` 固定 SHA-512；保留禁用后缀和默认禁用项。1.21.11 使用 Java 21，缺少时自动准备；1.8.9 自动准备 Java 8、对应平台原生库和固定性能包。
- 1.8.9 性能包暂不接受额外任意 JAR。OptiFine 从作者原站下载，不放入安装包分发。
- 补回已上线 0.2.22 的多行 Fabric 元数据及通用 Fabric/NeoForge JAR 去重修复，避免旧分支回归。

## 好友服务

从实际部署的 `unbox-client-friends` 下载备份，只修改房间版本/加载器允许列表与 Beta channel 保留。没有直接用旧工作分支覆盖整个生产 Worker。原 D1、两个 secret bindings 均保留，未迁移数据库。

生产允许 26.1 / 26.1.2 / 26.3 的 Fabric、NeoForge，新增 1.21.11 Fabric / 1.8.9 Forge。9 项房间函数兼容性检查通过；部署后 `/health` 返回 200 且 configured=true。此检查不代表两地真实账号邀请完整实测。

## 发布及后续维护

更新沿用原 updater 公钥；版本化文件先上传并校验，两平台就绪后最后更新 latest.json。公开 Release 为 v0.2.23，明确说明客户端 Beta 状态，但不使用会被旧更新器跳过的预发布版本号。

编译资源固定在该 Release 的 `beta-resources.zip`；Windows workflow 校验 ZIP SHA-256 后构建，不从另一开发工作区临时取文件。GPL/LGPL 原生移植的对应源文件及许可证随资源包提供，也保留仓库源码。

不要把 Linux 或 Intel Mac 写成此次支持平台。macOS 沿用本地 ad-hoc 签名和独立 updater 签名，没有 Apple Developer ID 公证；更新签名校验与 Apple 公证是不同环节。

旧 GitHub 更新通道的 latest.json 使用 GitHub 附件 URL；现行 Cloudflare 通道使用 Cloudflare URL。两份清单指向相同签名包，兼容各自的下载来源限制。
