# Unbox Client：交互审查与 26.1 实现依据

查阅：2026-10-06。这里区分竞品资料、玩家个案、设计判断与本项目实测；不把营销数字当成可复现的性能结论。

## 结论

现有功能基本有必要，但不是每项都应默认开启。Launch、Profile、个人模组、共享玩法环境应该是四种清楚分开的对象。用户最常做的操作应直接完成；设置应在需要时出现。客户端的价值不是多几个 FPS/CPS 开关，而是环境准备可靠、个人设置不被覆盖，以及稳定的帧时间。

目前有证据支持“这些模式已有真实使用”，没有证据支持“所有玩家都认可”或“Unbox 比所有客户端更快”。UI 原型不能替代用户任务测试。

## 功能与交互取舍

| 功能 | 必要性与默认行为 | 交互与图标 |
| --- | --- | --- |
| Launch | 最高优先级，只启动已选 Profile；准备过程与错误真实可见 | 大按钮 + 26.1；下载与运行不能重复提交 |
| Profile | 必须隔离 mods/config/saves，同时共享经校验的公共资产 | 加号创建；原版物品栏风格方块缩略图；悬停暴露名字 |
| 四步创建 | 用户明确指定，采用 Name → Version → Loader → Icon，每一步确认，可回退保留输入 | 26.1 下拉框仅一个选项并说明支持范围；最后才创建，不自动开游戏 |
| 性能组件 | 默认受控组合，避免无依据堆叠；这类 JAR 在启动时装载 | 仪表图标 + 组件详情；不是可热卸载的布尔开关 |
| FPS / CPS | FPS 有诊断价值；CPS 对 PvP 有用但非所有玩家需要，默认关闭 | 波形/鼠标；显示真实数值，不填演示 FPS |
| 准星 | 常见视觉偏好，默认原版；打开后可改颜色、大小、间距 | 准星图标；即时预览并能恢复原版 |
| 粒子 | 视觉清晰度及性能取舍，默认保留原版 | 星点图标；密度减少不改变服务器游戏结果 |
| HUD Editor | 核心入口，属于操作，不是一个可以关闭的模组 | 四向移动图标；Done 保存，Esc 撤销本次移动 |
| 装备 / 坐标 | 生存玩家也有价值；拆成两个独立开关 | 盾牌 / 罗盘；不把两个不相关偏好绑在一起 |
| Toggle Sprint | 常见输入偏好，默认关闭 | 键盘图标，遵守正常冲刺条件 |
| Chat | 有用；默认不开额外修改 | 对话气泡；参数须明确是背景、字号还是消息行数，不能混称 |
| Zoom | 常见，绑定 C，可在原版 Controls 改键 | 放大镜加号；按住生效，松开恢复 |
| Freelook | 可选且受服务器规则约束，不默认开启 | 眼睛图标；版本实现未验证时禁用并解释 |
| OptiFine Cape | 只显示已有披风，不安装 OptiFine 渲染器 | 衣着图标需要文字补充“Cape”，不能单靠图标区分皮肤与披风 |
| News | 优先级低，保留用户认可的区域，不加入广告和寒暄 | 两张有图内容卡；优先真实版本与开发信息 |
| Friends | 联机主流程必要；离线时不能显示伪造好友与在线状态 | 真实头像/ID/状态；云端不可用时显示连接状态 |
| Mods / Packs / Shaders | 必须绑定当前 Profile；每行两项 | 文件存在不等于已启用；缺少光影加载器要解释 |

四步创建比单页多点击，这里尊重用户指定的流程。通过默认 Fabric、只支持 26.1、保留草稿和自动匹配运行时，减少每一步需要理解的内容。循环皮肤列表需要真实库存，不能用重复假皮肤填满；不足 3.5 项时只显示实际项。

## 26.1 的硬边界

[Fabric 26.1 迁移说明](https://www.fabricmc.net/2026/03/14/261.html)明确了 Java 25、无混淆发布与新的 Loom 工作流；旧模组至少需要重新编译。HUD 改用当前渲染提取接口。已在本机用官方 26.1 client.jar 和 Fabric API 对照 `javap` 检查签名，并编译 Unbox 模组。

已查询 Mojang manifest、Fabric Meta、Forge promotions、NeoForge Maven 和 Modrinth API。原始响应保留在 `research/`。Forge 的 26.1 版本确实存在，因此界面不能写“不存在”，只能写“Unbox 尚未完成集成”。26.1 是精确目标，不自动升级到 26.1.1/26.1.2 或最新版本。

## FPS 方案：先复用，再测量

先复用成熟组件；当前没有证据证明另写渲染器值得。锁定清单在 `src-tauri/resources/performance-lock.json`，包含上游版本 ID、下载地址和哈希。使用原作者发行文件，保留归属，不把代码改名包装成自主优化。

- [Sodium](https://github.com/CaffeineMC/sodium)：渲染优化；不与 OptiFine 渲染器混装。
- [Lithium](https://github.com/CaffeineMC/lithium)：逻辑效率，改善不必体现为平均 FPS。
- [ImmediatelyFast](https://github.com/RaphiMC/ImmediatelyFast)：即时绘制批处理，不叠加我们自己未经验证的同类缓存。
- [Entity Culling](https://modrinth.com/mod/entityculling)、[FerriteCore](https://modrinth.com/mod/ferrite-core)、[Dynamic FPS](https://modrinth.com/mod/dynamic-fps)：分别处理遮挡、内存、后台资源；不把后台降帧宣传成前台性能提升。

不默认加 C2ME、Vulkan 替换、大量 JVM 魔法参数或所有名字里带 Fast 的模组。版本兼容只是第一道门槛，还需集成启动、真实世界和硬件测试。尤其 macOS 的图形驱动不能与 Windows 独显测试互相替代。

可探索的增量是：启动器不可见/游戏运行时停掉动画；HUD 数据低频刷新而非每帧格式化；异步工作不占渲染线程；共享资产缓存及严格依赖锁定。当前实现的缓存和低频刷新属于工程措施，不构成“超过 Lunar/OneClient”的结论。

### 性能验收方法

同一 26.1、Java 25、世界副本、路线、分辨率、渲染距离、模拟距离、材质和光影。预热后每组至少三次 60 秒采样，记录中位 FPS、1% low、p95/p99 帧时间、>50ms 卡顿次数、内存和 GC。对比原版、Unbox 核心、Unbox+优化集合、其他支持相同版本的客户端。同时测无光影、光影、密集实体、快速加载区块。不能用菜单 FPS 或改变画质来冒充优化收益。

## 云端与开发状态

Wrangler 已实际执行 `whoami`，返回未认证。随后发起 OAuth 登录，但未取得用户登录结果，因此尚未部署到该账户。不存在“已使用 Cloudflare 免费额度”的假完成状态。免费 Workers/D1 只适合元数据和信令；不能当 Java 服务器或无限游戏流量中继。

Microsoft 正版登录也需要属于本项目的应用注册；不借用其他启动器 client ID、不读取其他软件 token。开发版本明确提供本地身份，不声称该身份可以访问在线认证服务器。

实际完成与未完成列表以 `IMPLEMENTATION.md` 为准。编译、原生窗口、资源下载、游戏启动和帧数基准分别验收。
