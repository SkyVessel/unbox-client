# 26.3 与 1.21.11 双端模组同步验证

日期：2026-11-14（运行日志按本机游戏时区显示部分为 11-15）。分支：`codex/port-1.21.11-1.20.1`。本轮仅本地开发与测试，未发布客户端更新或部署好友服务。

## 实际结果

| 版本 / 加载器 | 房主额外模组 | 访客初始状态 | 实际网络下载 | 重启后的结果 |
| --- | --- | --- | --- | --- |
| 26.3 Fabric | 客户截图中的全部 35 个 JAR，使用截图版本 | 无上述 35 个 JAR，仅 Unbox 基础功能/性能依赖 | 207,183,418 字节，26 个共享模组 | 进入房主世界；双方清单 ID/SHA-256 一致；收到区块并保持 200 游戏 tick |
| 1.21.11 Fabric | 上述项目中可用的 30 个对应版本 JAR | 无上述 30 个 JAR，仅该版本基础依赖 | 73,165,606 字节；清单为 22 个共享模组 | 进入房主世界；双方清单 ID/SHA-256 一致；收到区块并保持 200 游戏 tick |

26.3 有 9 个额外 JAR 标记为仅客户端模组，不强制同步。1.21.11 的 22 个共享项包含 21 个客户模组和原有基础依赖 owo-lib；后者从访客本地校验后复用。重启后再次握手两版均为 0 下载字节、无需再次重启。这里的“再次握手”指下载完成后的重启入世，不是另做了一次退出世界再加入。

证据位于 `research/verification/customer-sync-2026-11-14/`：每版的 `customer-mods.json`、`shared-manifest.json`、`result.json`、`initial-guest-check.json`、`host-world-checks.json`、`guest-world-checks.json`、`world-events.log`。26.3 最终运行标识为 `customer263-final`；1.21.11 为 `customer12111-04`。

这是两个真实 Minecraft 进程，实际通过登录阶段的加密连接传输 JAR；访客退出后调用真实 Rust `sharing::apply` 校验并准备独立好友环境，再启动新的 JVM 自动重连。不是提前放好客户模组后只检查加载，也不是仅做扫描或单元测试。

### 实测范围

- 同一台 Mac 上的两个实际客户端，直连 LAN；两个独立本地测试身份；好友信令使用本地 Worker 与内存数据库。
- 测试用 `PrivateWorldSmokeTest` 仅替换独立 JAR 副本中的自动操作驱动；共享、身份握手、下载、校验、原生环境准备均使用实际实现。此替身和隐藏窗口 agent 不进入交付 JAR。
- 创建全新独立世界；不打开用户存档，不移动视角，不移动角色、不进行鼠标平滑测试。WorldWeaver 首次欢迎页通过正常关闭动作确认。
- 没有完成两地家庭网络、公网好友 Worker、真实微软账号认证或启动器 UI 点击到自动重启的端到端测试。本轮重启由测试协调脚本调用原生准备函数后拉起真实游戏进程。
- 1.21.11 在启动器普通 Profile 创建/启动流程中仍未全面开放。本轮为其原生共享文件准备增加了 Fabric 范围支持；未以测试结果冒称启动器发布版已完整支持 1.21.11。

- Kaleidoscope Immersive Eating：作者 [CurseForge 文件列表](https://www.curseforge.com/minecraft/mc-mods/kaleidoscope-immersive-eating/files/all)列出 26.3 / 26.2 / 26.1.2 / 1.21.1 / 1.20.1，没有 1.21.11。

Cinematic Interactions 使用作者公开的 [1.21.11 文件 9345424](https://www.curseforge.com/minecraft/mc-mods/cinematic-interactions/files/9345424)，其余从 Modrinth 对应版本下载。精确文件、版本、SHA-256 及解析结果已保留。

## 本轮发现并修复的问题

### 1. 同一 JAR 存在两个文件名，导致共享清单失败

1.21.11 同步后的 owo-lib 同时存在“下载哈希.jar”和原基础依赖名称。Fabric 能加载完全相同的重复 JAR，但原 `EnvironmentManifest.scan` 产生重复 ID，最终 `validate` 报 `Invalid shared file manifest`。失败可用真实同步后的访客目录稳定复现。

修复：扫描时以模组 ID 和 SHA-256 去重。同 ID、相同字节只共享一次；同 ID、不同字节仍明确拒绝，并指出文件名。没有关闭哈希校验或放宽远端清单的重复 ID 校验。`EnvironmentPreparationTest` 同时验证相同副本可用与不同副本仍拒绝。

此路径也可能导致房主出现客户所见的通用准备失败，但没有客户日志，不能认定就是该客户的唯一原因。

### 2. 重启后资源加载期间提前加入，随后被主菜单取消

1.21.11 第三次实际测试中，自动加入发生在首次资源加载尚未完成时。后续主菜单替换触发 `SocialBridge.cancelJoin()`，清除了共享握手的邀请上下文。房主随后显示 `Update Unbox on both computers to synchronize mods.`，访客显示同步失败。网络阶段记录为 `accepted → route_search → connecting → cancelled`。

修复：自动重连在主线程检查启动遮罩已经消失、当前处于主菜单/加入进度页，才消费重连记录并立即加入。没有人为增加固定等待时间。26.3 和 1.21.11 均重新跑完整双端流程通过。共享接收失败也增加实际异常日志，并给重复清单、已取消邀请等内部原因提供可定位文字。

### 3. 1.21.11 原生共享文件准备缺少版本准入

Rust 原先只接受 26.x 清单，1.21.11 下载完成后会被拒绝为 `Unsupported shared environment`。增加独立的 `shared_supported(loader, version)`，只扩展到已经有原生构建的 1.21.11 Fabric；不开放 1.20.1、1.21.11 NeoForge 或普通创建 Profile。该规则有加载器边界回归检查。

## 前一轮修复在本次实际流程中的验证

BetterEnd 等 JAR 的 `fabric.mod.json` 包含字符串内的原始换行，Fabric/Gson 能解析，原 Rust 严格 JSON 解析会失败。`fabric_metadata.rs` 仅对有界 UTF-8 元数据中字符串内部的控制字符转义，其他语法错误继续拒绝。此次 26.3 完整下载和原生准备实际覆盖了 BetterEnd，不再只是预置缓存单测。

房主扫描失败信息现在指出具体文件；缺失的已选资源包/光影仍明确拒绝，不会静默丢弃共享内容。使用 Gson 2.14.0（26.3）和 2.13.2（1.21.11）分别回归。两者都可读取截图这些模组的换行描述，故不能把 Gson 版本差异称为已定位根因。

## 与微软服务的关系

本轮复现的重复清单、启动取消、Rust 元数据兼容问题均发生在本地文件/Unbox 同步链路，不依赖微软服务故障。测试使用本地身份，日志中的 Microsoft/Realms 401 是没有真实微软令牌的预期结果，不代表微软服务器崩溃。

先前检查的公开微软端点可达也只说明检查时可达。没有客户日志、故障时间的服务状态或真实账号复测，仍不能证明客户原始问题一定由哪个路径触发，或彻底排除当时的微软认证故障。

## 复跑入口

1. 依照保留的 `customer-mods.json` 下载对应原始 JAR，并逐个核对 SHA-256；准备该版本已有的 Minecraft 运行库及 Unbox 基础依赖。
2. 构建原生正式客户端。26.3 用 `UNBOX_MINECRAFT_VERSION=26.3 sh scripts/build-mod.sh`；1.21.11 用 `./client-mod/gradlew -p client-mod remapJar -Pminecraft=1.21.11`。
3. 构建测试副本：26.3 用 `python3 scripts/build-customer-sync-fixture.py`；1.21.11 用 `./client-mod/gradlew -p client-mod -I ../tests/customer-sync/fixture.gradle remapCustomerSyncFixture -Pminecraft=1.21.11`。
4. 在 `.cache/customer-sync/silent-agent` 生成兼容 Java 21 的隐藏窗口 agent：`UNBOX_SILENT_AGENT_OUTPUT="$PWD/.cache/customer-sync/silent-agent" UNBOX_SILENT_AGENT_JAVA=21 python3 scripts/build-silent-agent.py`。
5. `cargo build --manifest-path src-tauri/Cargo.toml`，生成实际原生同步准备程序。
6. `UNBOX_MINECRAFT_VERSION=26.3 UNBOX_CUSTOMER_MODS="绝对路径/客户JAR目录" node scripts/test-customer-sync.mjs unused 全新运行名 --local-host --sync-mods`。1.21.11 替换版本及模组目录。`unused` 为保留的旧入口位置参数，测试实际创建新世界，不使用该路径的存档。
7. 检查 `.cache/network-tests/运行名.json`、两个客户端的世界检查及清单哈希；不能只以退出码、单元测试或游戏窗口出现判定通过。
8. 归档精简证据后清理该运行目录、下载 JAR、共享缓存与测试副本。不得递归清理其他版本现有 Profile 或公共运行库缓存。
