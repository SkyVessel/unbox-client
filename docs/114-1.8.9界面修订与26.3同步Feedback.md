## 1.8.9 完整 UI

- 人物预览：修正鼠标跟随与拖拽的方向；降低跟随角度随鼠标距离变化的敏感度。预览退出时同步 OpenGL 实际纹理绑定与 Minecraft 的纹理状态缓存，避免下一个控件复用错误状态。
- 本地皮肤：皮肤列表与 PNG 由启动器分别写入，读取中间状态时可能暂时无法解码。现在仅在新图像有效或明确取消当前皮肤时更新签名和纹理；临时失败继续保留旧纹理并重试，不再把失败结果永久缓存。
- Appearance：使用 26.3 New UI Beta 的同一套矢量页面素材。左侧三项皮肤缩略图及滚动、人物预览、Classic/Slim 选择、Use skin 确认；右侧 Unbox/Crown/Cash 资产卡、拥有状态及 Equip。选择预览不立即更换皮肤，点击 Use skin 才通过现有启动器桥接应用。预览 PNG 限定内容寻址文件名与尺寸，在后台解码。
- 主菜单与 Right Shift 快捷菜单：Feedback 改为左下角 104×32 逻辑尺寸，字号 17，随窗口底部定位。原性能设置中的 Feedback 入口仍可使用。
- 本机唯一 Clean Test 已从 Profile 列表移除。新版启动器在加载/保存 Profile 时也会移除这类临时条目，取消新建入口并拒绝继续启动。保留目录中的存档和配置，不自动转成完整 UI Profile、不删除用户世界。旧测试引擎源码和资源仍保留用于历史可复现性。

## Ping 测量口径

依据本机已有 Lunar 1.8.9 调查（第 108 篇及 `.cache/lunar-analysis/ping/bridge-source`）：其 Ping 模块调用服务器列表的 ServerPinger。

1.8.9 HUD 改用原版 `OldServerPinger` 的状态 ping/pong，在单独后台线程每 10 秒查询一次当前服务器地址。停止向游戏连接发送 REQUEST_STATS。切换连接/地址会清空样本，单人世界不测量，失败或超过 30 秒无新样本显示未知。轮询最长 5 秒；DNS 解析由系统处理，也在后台。

此数值与 Lunar 属于同一种测量口径，未通过常量扣除或平滑伪造数字。服务器状态连接与对局连接是不同连接；结果不是每次攻击的响应耗时，也不保证两个客户端在不同时间或解析到不同节点时读数完全相同。本轮未修改游戏封包、中继、代理或击退机制。26.3 的 HUD 延迟算法未改动。

## 26.3 同步 Feedback

当前接入 **26.3 New UI Beta 的 Fabric / NeoForge**，入口同样在主菜单和 Right Shift 菜单左下角。Classic 是否需要加入已向用户询问，尚未收到选择；本轮保留 Classic 引擎原样。

操作：Feedback → Start recording → 接受好友邀请并复现同步失败 → 正常退出游戏，保持启动器运行。Stop & discard 会取消记录和上传。默认关闭，每次游戏进程重新启动后恢复关闭；自动同步重启也会结束当前段记录。

记录内容：

- 账号 UUID 与会话号；服务端使用实际认证账号绑定名称和身份。
- 加入过程、直接/P2P/中继路线分类、房主清单准备、清单校验、文件下载开始、缓存命中、完成校验、断线及清理阶段。
- 文件 ID、字节数、总量、异常类型和有限的错误分类（校验失败、超时、取消、权限、磁盘、清单等）。
- 游戏结束后，启动器完成共享环境校验/应用，再加入 launcher_applied / launcher_failed 等结果并上传。

不发送聊天、账号令牌、邀请授权、文件内容、完整路径或任意异常原文。游戏/网络线程仅追加内存事件；文件写入在后台进行。最多 120 条事件、每份 48 KB，超过条数保留最近事件。周期落盘便于本地保留，但只有主动开启且正常退出产生的最终报告会自动上传；强制杀进程的未完成文件不会被当成同意上传的新报告。

路径沿用 `logs/unbox-feedback-recording.json` → `logs/unbox-feedback.json`，上传结果保存在 `logs/unbox-feedback-status.json`。未开启不生成上传报告。会话与账号必须匹配；失败保留本地文件，下次启动隔离旧文件，不自动冒用新的账号重发。

## 服务端

沿用现有好友 Worker 的私有 `/v1/connection-feedback`，新增 schema=2、kind=mod-sync；旧 schema=1 的 1.8.9 报告兼容。仅替换线上 `connection-feedback.mjs` 模块；部署前后下载核对，其他模块与绑定完全保留。

沿用 7 天保留、每账号每天 4 份、全局 2,000 行的限制；同会话幂等。管理员继续从好友服务 D1 的 `connection_feedback` 查找，按账号及时间缩小范围，检查 report 中的 events。该表没有公开读取 API。达到限额或网络失败时记录保留本机，状态文件注明失败。
