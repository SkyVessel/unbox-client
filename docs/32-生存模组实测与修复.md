# 生存模组实际验证与修复

2026-10-15。用户已允许启动游戏与测试。本轮在 macOS ARM64 使用隔离存档副本和离线测试身份；没有打开、改写原始玩家世界，没有发布 GitHub 更新。

## 修复

1. **大地图头像缺失**：实际截图出现紫色方块，日志对应 `minecraft:entity/player/slim/alex` 缺失。26.1 的皮肤资源 ID 不等于纹理路径；改为 `skin.body().texturePath()`，重新截图确认头像正常。
2. **退出游戏时地图纹理线程错误**：Fabric 断线回调在 Netty 线程直接释放 GL 纹理，实测出现 `Rendersystem called from wrong thread`。两加载器断线清理统一调度到客户端线程；重连及退出日志复查未再出现此错误。
3. **联机初次接收死亡点的时序问题**：LAN 先使用地址标识建立地图，世界 UUID 和死亡包随后到达；原 tick 中切换地图身份会清除刚收到的死亡点。将身份变更清理放到世界身份包处理期间，先清理旧状态，再接收死亡点。真实双客户端包顺序验收通过。
4. **NeoForge 26.1 启动崩溃**：VeinMiner 2.10.4 引用了当前 NeoForge 26.1.0.19-beta 不存在的 `BreakBlockEvent`。核对官方标注该版本的全部 7 个候选，均有相同接口依赖。该目标不再安装 VeinMiner、其 Hotkey 和闲置 KLF，设置页给出明确原因；26.1.2 保留正常功能。
5. **旧依赖与冲突保护**：已受管且与旧清单哈希一致的不兼容文件先备份再移出；用户自行放入或修改的文件保留并给出可操作错误，避免静默删除或启动后才崩溃。补充了真实临时目录回归测试。
6. **测试结果真实性**：更新旧盔甲架/自制排序验收，使其使用石头墓碑与真实第三方引擎；运行器遇到 `ok:false` 会失败，不能仅凭报告文件存在算通过。

## 验证范围

- 前端/交互自动检查：42 项通过。
- Rust 安装、身份、共享和数据保护检查：59 项通过。
- Fabric / NeoForge × Minecraft 26.1 / 26.1.2 四组独立构建成功；四组游戏验收结果在下表列出。没有转换或伪造上游兼容声明。
- Right Shift UI 在完整 Fabric 26.1 模组组合中通过 140 项检查，包括所有新模块设置页面、滚动、改键、保存，以及有权限时实际执行死亡点传送。无权限时停留地图并提示原因。
- ItemPhysic：读取真实上游配置、验证关闭门控；苹果和平面物品/石头方块经实际 renderer 提取非空模型，再由上游提交非空几何。此检查验证渲染提交链路，不等于 FPS 基准测试。
- IPN：打开真实库存界面调用上游整理，服务端库存顺序发生变化，所有物品总数、名称等组件保持，鼠标库存为空。
- VeinMiner/FallingTree：走真实服务端破坏方块及加载器事件；关闭时仅原点破坏，开启时矿脉/树木按规则处理。此测试暂时使用 VeinMiner 官方无客户端热键模式和 FallingTree 瞬间处理模式，未将它描述成真实键鼠热键或所有砍树动画验证。
- 地图：负区块坐标、后台写入后重开、异步读写合并、关闭时仍有待处理读取、世界/维度隔离；每 UUID 最新死亡、同名队友记录、M/Esc/改键。
- 墓碑：真实致死与重生；完整背包、盔甲、副手、鼠标物品、伤害值、名称与消失诅咒；同名不同 UUID 拒绝取回；石头挖掘计时；精确掉落、主人拾取、姓名清除；keepInventory。
- 完整重启：Fabric 26.1 与 NeoForge 26.1.2 分别用两个 JVM 完成“死亡 → 留下未领取墓碑 → 正常保存退出 → 重启 → 读取 → 挖掘取回”。预期物品取自死亡前库存，避免只比对墓碑自身。
- 双客户端：Fabric 26.1 与 NeoForge 26.1.2 分别进行同机 TCP 联机，验证三项房主玩法开关的开启→关闭→开启、世界 UUID 与队友死亡包。重新以普通服务器类型连接，相同真实包不能启用受限功能。
