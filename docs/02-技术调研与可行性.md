# 技术调研与可行性

版本：0.1｜查阅日期：2026-10-05｜用途：支撑产品功能评审

本文件区分三种信息：**已查证**是官方文档或项目说明；**产品建议**是基于资料提出的方案；**待验证**需要代码原型、设备、真实网络或账号才能得出结论。本轮未进行游戏性能实测、联机原型、许可证法律评估或 Cloudflare 账号检查。

## 1. Feather 参考页面的实际含义

用户提供的地址带有重复 Markdown 转义，本轮使用其可访问的原始地址 [Feather Mod Management](https://docs.feathermc.com/server-api/mods/)。

已查证：它是 Server API 的模组管理文档，列出部分常见内置功能，并说明服务器可阻止或启停功能。它不是完整模组安装清单，也没有证明其每项内置能力可供第三方独立下载或复用。

本产品借鉴 FPS、自由视角、准星、坐标和延迟显示等体验目标，以及“服务器能够限制客户端功能”的规则。其余功能范围由用户目标决定；不复制 Feather 品牌、素材、界面或假定能调用其闭源内部实现。

## 2. 性能优化：候选、逻辑与二次开发边界

“常见候选”指此次调研中官方项目明确定位于相关问题的工具，不是全网流行度排名。不同版本、加载器和硬件的支持范围必须以最终选定文件为准。

| 候选 | 已查证的主要作用 | 对本产品的启发/建议 | 不能据此承诺 |
|---|---|---|---|
| Sodium | 优化客户端渲染，提高帧率、减轻微卡顿 | 作为兼容组合候选；围绕渲染瓶颈测量 | 每台设备固定增益、任意版本可用、可随意复制源码 |
| Lithium | 优化游戏逻辑，客户端/服务端均可使用，不要求两端同时安装 | 区分渲染与逻辑负载；房主整合服务也要测 | 玩家安装就能修复远端服务器卡顿 |
| FerriteCore | 降低内存使用，部分收益适用于服务端 | 为大型包测峰值内存与 GC 停顿 | 内存下降必然同幅度提升 FPS |
| ImmediatelyFast | 优化即时渲染，通过缓冲和批处理改善 GPU 数据上传 | 自研 HUD 与轻量扩展优先减少重复绘制和上传 | GPU 已满载时仍有同样收益 |
| ModernFix | 启动、内存及兼容性修复相关优化 | 大型包测启动阶段，不仅看游戏内帧率 | 所有可选优化都适合默认打开 |
| Entity Culling | 避免绘制被遮挡的实体等内容 | 场景相关剔除，检测模组渲染兼容 | 所有透明、特殊渲染和光影组合无异常 |
| Dynamic FPS | 降低后台、闲置、电池场景的资源使用 | 启动器与游戏分离管理后台负载 | 其主要作用是提高前台 FPS |
| spark | 性能分析工具 | 用采样找瓶颈、验证回归，按需启用 | 装上分析工具本身就能加速 |

对应官方来源：[Sodium](https://github.com/CaffeineMC/sodium)、[Lithium](https://github.com/CaffeineMC/lithium)、[FerriteCore](https://modrinth.com/mod/ferrite-core)、[ImmediatelyFast](https://github.com/RaphiMC/ImmediatelyFast)、[ModernFix](https://github.com/embeddedt/ModernFix)、[Entity Culling](https://modrinth.com/mod/entityculling)、[Dynamic FPS](https://modrinth.com/mod/dynamic-fps)、[spark 文档](https://spark.lucko.me/docs)。

### 2.1 从优化逻辑转化为本产品研发任务

以下是待验证的研发方向，不是已经完成的源码级研究或保证有效的补丁。

| 优化问题 | 研发任务 | 证明方式 |
|---|---|---|
| HUD 和扩展重复工作 | 合并同帧绘制，缓存不变文字与布局，避免每帧序列化大量状态 | 比较 CPU 采样、绘制调用及 p99 帧时间 |
| 不必要的状态轮询 | 优先事件更新；对坐标等高频值按实际显示需要采样 | 测空闲和战斗时的开销 |
| 反复分配造成 GC 压力 | 找到实际分配热点后减少临时对象；不盲目增加缓存 | 测分配速率、堆占用、GC 暂停和泄漏 |
| 启动器抢占资源 | 游戏中停止持续目录扫描、降低动画和轮询、限制下载解压并发 | 三组基线分别测启动器开启/后台/退出 |
| AI 编译影响游戏 | 编译放独立进程、可暂停和限制资源 | 对比生成任务运行时的帧时间长尾 |
| 模组组合不匹配 | 建立按游戏/加载器/设备/整合包分组的认证配置 | 每组执行启动、游玩、退回和回归用例 |
| 诊断把网络当性能 | 同时读本地帧时间与服务端 tick 指标，单独测网络 | 人为注入各类故障，验证解释正确性 |

优先修复我们自己引入的成本和已测到的兼容问题，再考虑修改成熟渲染器。对上游的深入改造应记录具体版本、许可证、代码路径、基准和维护责任。

### 2.2 许可与整合方式

Sodium 当前仓库说明采用 Polyform Shield 1.0.0，不能把“源码公开”当作允许任意竞争性产品改造与分发的结论。具体用途需核对目标版本条款，必要时取得作者许可。链接：[当前许可证](https://github.com/CaffeineMC/sodium/blob/dev/LICENSE.md)。

Lithium 与 ImmediatelyFast 的项目页标注 LGPL-3.0，FerriteCore 标注 MIT。正式选型仍需核对下载文件对应版本及依赖的许可证，并履行适用的署名、源代码等义务；本轮不作法律结论。许可状态和获得授权的日期应写入发布检查记录。

可选实现路径：直接通过允许来源安装已发布组件；在符合许可条件下维护补丁；向上游贡献；围绕公开行为独立实现辅助逻辑。不能预先把“复制优化代码到自己的客户端”视为唯一方案。

## 3. 热加载：真正可交付的范围

已查证：Fabric 有开发环境中的类/Mixin 热替换文档；这类调试能力不是面向任意用户、任意模组安全装卸的产品契约。KubeJS 则明确区分 startup、server、client 脚本，注册类行为需要重启，部分世界生成变化需要重新进入世界。来源：[Fabric 启动与调试](https://docs.fabricmc.net/develop/getting-started/intellij-idea/launching-the-game)、[KubeJS](https://kubejs.com/)、[startup scripts](https://kubejs.com/wiki/folder-structure/startup-scripts)。

产品建议：建立自己的“轻量扩展”边界；常驻桥接模组预先安装，在游戏运行中接受受限脚本或声明式扩展。对外说清支持的功能类型，不称为通用 JAR 热加载。

| 技术路线 | 可行用途 | 主要问题 | 初步态度 |
|---|---|---|---|
| 配置与声明式组件 | HUD、提醒、准星、简单条件触发 | 表达能力有限 | 适合最先验证 |
| 受限脚本运行时 | 条件、计时、事件与轻量绘制 | 指令预算、中止、API 逃逸、状态清理 | 通过隔离验证后扩展 |
| KubeJS / 数据包适配 | 配方、标签、规则与已支持事件 | 版本差异、权限、重载副作用；不能假定脚本天然安全 | 作为受控高级适配 |
| 独立 Java 类加载器 | 少量受限开发插件 | 静态引用、线程、注册表和卸载不可靠 | 不作为首发普通用户方案 |
| 调试器/JVM 类替换 | 开发者调试 | 部署条件、结构变化及 Mixin 边界 | 开发工具，不作为核心用户承诺 |

必须先验证的失败案例：死循环、递归过深、过量内存、渲染异常、监听器遗留、状态迁移失败、旧版本恢复和宿主 API 不匹配。只有可被中止的执行模型，才有资格承诺“生成错了也不冻住游戏”。

全房间更新以服务端版本为权威，客户端准备完成后切换；不能把分布式网络当作可以瞬时无条件同步的内存。

## 4. 异地联机方案比较

“最简单”需要分别看房主操作、朋友操作与部署/运营工作。把运维难度藏到后台并不会让成本消失。

| 方案 | 用户路径 | 官方资料支持的特点 | 对本产品的适用性 |
|---|---|---|---|
| Essential | 在世界或菜单托管，再邀请朋友 | 使用 ICE/TURN；官方 FAQ 说明要求正版认证；模组玩法仍要一致 | 借鉴邀请体验，不能直接满足混合身份和共享环境的全部目标 |
| e4mc | 房主安装、开放 LAN、分享地址 | 官方说明朋友不需要安装 e4mc；项目与服务端公开 | 可研究代理分享思路；“朋友无需装 e4mc”不等于无需安装玩法模组 |
| playit.gg | 房主运行代理，朋友用地址连接 | 官方提供游戏服务隧道 | 可作为备选路径评估，需核查区域、免费限制、嵌入许可及稳定性 |
| Tailscale | 设备加入受控网络再连接 | 官方说明有 NAT 穿透和中继相关机制 | 适合高级用户/排障；默认让朋友配置账号网络不够简单 |
| 自研启动器内置连接层 | 只接受邀请 | 是本产品设想，并非现成验证结果 | 与共享环境最容易统一，但需解决穿透、中继运营和身份验证 |
| 公网端口映射 | 房主配置路由器，分享地址 | 常规技术路径 | 不作为默认新手流程；已有可达环境可复用 |
| 独立常驻服务器 | 一次部署，朋友随时加入 | 不依赖房主游戏进程 | 需要实际持续运行的主机与预算 |

来源：[Essential 托管流程](https://essential.gg/en/wiki/start-hosting)、[Essential FAQ](https://essential.gg/wiki)、[e4mc 官方](https://e4mc.link/)、[playit.gg 官方](https://playit.gg/)、[Tailscale 网络说明](https://tailscale.com/docs/reference/faq/firewall-ports)。上表未引用未经验证的第三方“全网最快”“永久免费不限量”等宣称。

建议在相同整合包与不同真实网络中比较：首连耗时、成功率、延迟、丢包下表现、掉线恢复、CPU 和中继流量。必须覆盖中国大陆与跨境网络的需求确认；本轮没有测试地区可达性。

若双方都安装我们的启动器，可以把本地隧道代理集成到应用内，减少用户操作；但第三方协议的授权、更新、杀毒误报和系统防火墙仍需处理。

**建议决策顺序**：先确定是否允许任何额外中继预算和目标地区，再选网络实现。仅有 Cloudflare 免费额度时，可以验证直连与有限免费备选，不能写下“所有网络都成功”的上线承诺。

## 5. Cloudflare：免费服务能承担什么

### 5.1 公共文档中的额度

以下为查阅日的公共计划说明，不代表用户账号尚有这些额度；额度也可能被其他项目共同消耗。计费单位和重置周期不能混用。

| 服务 | 免费额度/限制摘要 | 拟使用方式 |
|---|---|---|
| Workers Free | 100,000 请求/天，HTTP 请求 CPU 时间 10 ms，内存 128 MB | 邀请、版本查询、权限和轻量 API |
| Durable Objects Free | 100,000 请求/天，13,000 GB-s/天；免费使用限于 SQLite 存储后端 | 房间协调和连接信令；适配休眠型 WebSocket，减少持续运行 |
| D1 Free | 每日 500 万行读、10 万行写，总存储 5 GB | 成员、发布版本、索引和必要记录 |
| R2 Standard 免费档 | 10 GB-month/月，100 万 Class A、1000 万 Class B 操作/月，公网出站免流量费 | 有权分发的小文件、扩展包；不存所有人的完整世界 |
| Spectrum | 免费计划不提供；Minecraft 不属于免费服务 | 不作为零成本 Minecraft TCP 入口 |

依据：[Workers 限制](https://developers.cloudflare.com/workers/platform/limits/)、[Durable Objects 定价](https://developers.cloudflare.com/durable-objects/platform/pricing/)、[D1 定价](https://developers.cloudflare.com/d1/platform/pricing/)、[R2 定价](https://developers.cloudflare.com/r2/pricing/)、[Spectrum 协议与计划](https://developers.cloudflare.com/spectrum/protocols-per-plan/)。各服务还有未在摘要中列完的限制，上线前必须按实际用法核对。

### 5.2 不混淆房间服务、信令、中继与游戏主机

| 责任 | 典型内容 | 建议归属 |
|---|---|---|
| 房间控制 | 谁可加入、玩法版本、成员状态 | Cloudflare 小型服务 |
| 连接信令 | 交换连接候选、建立会话 | Cloudflare 可承担，须按用量设计 |
| 实际游戏流量 | 长时间双向传输 Minecraft 数据 | 优先直连；失败走已验证的中继 |
| 游戏计算 | 世界 tick、模组逻辑、存档 | 房主电脑或自有远程主机 |
| 模组分发 | 模组 JAR 和资源 | 原项目允许的渠道优先 |

Cloudflare Tunnel 的公开 TCP 访问是通过 WebSocket 传输，终端通常需要 `cloudflared access tcp`；官方对长连接建议使用另一种 Client-to-Tunnel 方式。因此它不等于把普通 Minecraft TCP 地址免费公开给所有原生客户端。来源：[Tunnel 协议说明](https://developers.cloudflare.com/cloudflare-one/networks/connectors/cloudflare-tunnel/routing-to-tunnel/protocols/)。

如果我们自带客户端代理，理论上可以研究 WebSocket 等中转方式，但这仍需验证条款、额度、长连接、吞吐、延迟和运营边界。它是研究项，不能因为“技术上能转字节”就被认定为免费可靠中继。

### 5.3 免费预算的闭环

1. 进入部署阶段后读取具体账号、计划、已有资源和消耗；只授予本项目必要权限。
2. 为每项服务定义日/月额度、安全余量、速率和单任务上限，按整个账号的共享额度计算。
3. 元数据查询用缓存和索引，避免高频全量轮询；文件从允许的原站直取，减少代理放大。
4. R2 对所有上传、下载和公开对象访问建立计量与限制，不留下可绕过预算的无限公开读入口。
5. 建议 70% 提醒、85% 暂停可推迟的新任务；阈值只是策略，不是 Cloudflare 自带的绝对防计费开关。
6. 免费硬限额服务到限后降级；具有超额计费的服务，若无法可靠控制账号整体消耗，先停用该功能或采用本地方案。
7. 不自动启用付费计划、付费中继、域名购买或新收费模型。

容量示例仅作计算：若某版本可共享扩展平均 20 MB，100 个不同版本约占 2 GB，尚未计入保留版本和存储计量周期；它不能推导“支持多少实际用户”。并发数、重试、索引写放大、WebSocket 活跃度和文件大小都影响成本，需压测。

## 6. 共享玩法的下载与授权限制

Modrinth `.mrpack` 定义了精确文件清单、哈希、下载和客户端/服务端区分，适合作为互操作基础。房主私有配置、平台凭据、房间身份和热加载状态仍需自己的数据模型。来源：[官方格式](https://support.modrinth.com/en/articles/8802351-modrinth-modpack-format-mrpack)。

CurseForge 允许作者控制第三方分发。即使一个文件可在网页下载，也不能由此推断允许客户端自动抓取并转存 R2。来源：[官方分发开关](https://support.curseforge.com/support/solutions/articles/9000207877)。

另据 2026-06-10 官方公告，CurseForge 计划从 2026-07-16 起要求直接 CDN 文件下载携带有效 API key，拒绝无效请求。这个时间早于本次调研日，但本轮没有实际请求测试其执行状态。正式集成须取得适用授权并验证客户端凭据分发方式、下载流程及 401 恢复，不能把服务端私密 key 写入公开玩法清单。来源：[CurseForge 下载鉴权公告](https://blog.curseforge.com/introducing-api-key-authentication-for-curseforge-file-downloads/)。

产品必须保留“该文件不能自动分发”的可理解流程。这是自动同步承诺的真实例外；可以通过优先推荐完整可分发的玩法减少例外，但不能绕过作者限制。

## 7. 混合身份的工程边界

邀请制和服务端身份绑定可以防止只靠昵称冒用，但它们不代替微软官方的正版凭据。离线身份只能进入管理员允许此模式的服务器，不能被描述为正版认证。

需要验证：目标加载器的登录握手、UUID 与玩家数据关联、签名聊天策略、皮肤、领地/权限模组和世界迁移。协议不兼容时只认证可用组合，不能统一关闭验证后宣称全部完成。

代理体系也有不同的信息转发模式及加载器适配，不应假定所有模组服务器可直接复用同一种插件。参考：[Velocity 玩家信息转发](https://docs.papermc.io/velocity/player-information-forwarding/)、[服务端兼容说明](https://docs.papermc.io/velocity/server-compatibility/)。这些资料提供工程参考，不代表已为本产品选定 Velocity。

游戏与模组的分发须按 [Minecraft EULA](https://www.minecraft.net/en-us/eula) 及适用授权处理。本文件不把离线模式的技术设计解释为游戏购买要求的例外。

## 8. 验证门槛与失败后的产品处理

| 门槛 | 必须拿到的证据 | 失败后调整 |
|---|---|---|
| 性能 | 认证硬件/整合包的对照数据、回归报告 | 缩小优化承诺或调整组合，不伪报倍数 |
| 热加载 | 生命周期、死循环中止、资源清理、回滚演示 | 限定为更小的声明式能力；不退回任意脚本直跑主线程 |
| 联机 | 实际网络矩阵与中继成本 | 标明适用网络，选择有限中继或重新评审预算 |
| 混合身份 | 双身份进入、防冒名、UUID/背包/权限连续性 | 实验性标记或延后该组合支持 |
| 共享整合包 | 从全新机器复现目标包，包含配置和受限文件异常 | 限定可支持格式/来源，给出真实手动例外 |
| AI | 代表需求集生成、验证、撤销与权限拒绝记录 | 保留手动功能；降低自动执行范围 |
| Cloudflare | 账号配置、预算限制、压测与费用观察 | 关闭无法保证免费边界的路径 |

目前结论：四个方向均可设计出有边界的产品闭环，但**通用热加载、无限免费中继、所有整合包混合身份、未实测的大幅性能提升仍不能当作已解决问题**。
