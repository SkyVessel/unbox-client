## 2. 六张界面的具体借鉴

| 参考 | 画面观察 | 我们采用的原则 | 对应到产品 |
|---|---|---|---|
| L1 启动首页 | 暗色底上有非常明确的启动按钮，导航与好友状态都可快速定位 | 一个最突出的主动作；朋友是否可加入应清楚可见 | 首页“开始玩”或“继续游玩”，朋友入口显示真实状态 |
| L2 登录入口 | Minecraft 大图与紧凑操作区并置，登录和访客入口主次明确 | 世界画面提供第一印象；主流程只给少数选择 | 首次进入、登录、接受邀请；不复制整列性能宣传 |
| F1 游戏内模组面板 | 游戏背景经过模糊，中央暗色面板以图标、名称和启用状态组织功能 | 场景仍可辨认，功能可识别，启停结果可看见 | 小功能管理；HUD、准星、粒子等按用途组织 |
| F2 聊天与好友浮层 | 中央会话区与侧边好友栏覆盖游戏，外围仍保留场景 | 辅助操作无需离开当前世界；头像、名称和状态有稳定位置 | 朋友邀请与 AI 助手；本产品合并为按需打开的单个辅助层 |
| F3 HUD 编辑 | 控件直接放在游戏画面里编辑，能看到实际位置与效果 | 所见即所得；在对象旁出现相关操作 | 拖动 FPS/HUD、准星预览、吸附、恢复默认与键盘微调 |
| F4 模组库 | 紧凑图标、名称与开关排列在同一工作区域，上方有少量管理操作 | 内容容易扫读，管理动作靠近对象 | 玩法包详情与模组清单；个人功能开关与共享包编辑使用不同语义 |

来源：[Lunar 首页](https://www.lunarclient.com/download)、[Lunar 3.0](https://www.lunarclient.com/news/the-new-launcher-is-here)、[原版 Feather 截图](https://feathermc.com/)。完整图片 URL 保留在参考清单中。

F2 实际是较大的会话区加好友栏，不是微型气泡；“轻量”指保留当前场景和按需覆盖，不代表原图占屏很小。设计不能把描述文字当作截图里不存在的特征。

取舍依据仍是用户的“极简”要求：减少 L1 的新闻与促销入口、F1 的多重标签与格子边界、F2 的并列辅助面板。保留其视觉识别和操作优点。F4 的开关不能暗示普通 JAR 随时生效；生效时间由真实能力决定。

## 3. 本项目的“好看”标准

**一个完整的 Minecraft 场景，一块安静的深色磨砂面板，少量一眼能看懂的动作。**

1. **先看见世界，再看见动作。** 背景有清楚的空间、光线和时间感；主操作仍是视觉焦点。不能为了展示壁纸让文字失去对比。
2. **布局像一个整体。** 导航、标题、列表和操作共用一个表面；用对齐、间距和明暗组织内容。默认没有分割线和卡片套卡片。
3. **玻璃有厚薄关系。** 场景清楚、主面板透出色彩、弹出层更实。不能把所有背景模糊成失去 Minecraft 特征的色块。
4. **色彩集中。** 中性深色承载操作，背景提供丰富颜色；同一时刻只突出一个主动作。不会每换壁纸就改变按钮语义颜色。
5. **图标有识别，文字有答案。** 设置、关闭等熟悉操作可只用图标；“加入朋友”“同步并加入”等核心动作必须有文字。
6. **打开前后有连续性。** 世界名称、当前进度和位置稳定；展开详情时保留上下文，避免整个界面跳动。
7. **克制的精致。** 普通圆角、准确间距、整齐排版和细腻反馈；不用发光描边、装饰仪表盘、霓虹渐变、全屏飘粒子堆砌氛围。

可见的游戏内容和场景应成为记忆点。产品界面使用易读中文无衬线，数字用清楚的等宽数字排版；不沿用选图板的宋体标题，不把像素字体用于长段操作说明。

## 4. 首轮布局和信息层级

这些是构图提案，需在后续实际页面中验证；不是用户已经选定的线框图。

- 窗口背景铺满 Minecraft 图片，主面板四周保留 24–48 px 的场景呼吸区；面板最大宽度 1280 px，宽屏不无限拉长文字行。
- 主面板内左侧约 88 px 用于导航，图标配短标签，与正文共用底面，不画垂直分割线。首轮建议“游玩 / 朋友 / 玩法”，设置置底；AI 按需展开。
- 页面顶部保留清楚的标题与简短状态；正文内用同一基线对齐图标、名称、说明和操作。
- 首页围绕最近的世界：世界名称、当前玩法包、可加入的朋友、一个主要按钮。没有存档时原位切换为“创建世界”；邀请可直接进入对应房间。
- 玩法页面管理共享玩法包；单个包内部再看模组清单。小功能属于对应世界的工具区，不把服务器插件、普通模组、热加载扩展混成同一种开关。
- 一级信息：当前世界和主要动作。二级：朋友、玩法、准备状态。三级：版本、路径、网络详情等按需展开。
- 侧边助手宽度初值 368 px。空间不足时改为覆盖式单层面板，不把正文挤成窄条。聊天层和朋友层不同时并列占满界面。
- 首轮桌面构图校验尺寸：1280×800、1440×900、1024×720。低高度允许正文滚动；关键操作保留可访问位置，避免固定最小尺寸把按钮推出窗口。
- 增大字号或缩窄窗口时先换行、折叠次要信息，再改成单列。操作含义不能依赖截断后无法阅读的短语。

## 5. 背景体系

所选背景是可并存的场景方向，不要求用户再从中选出唯一一张。每个一级页面有稳定背景，返回时保持一致；搜索、切标签、调开关不会反复切换壁纸。

| 已选背景 | 氛围判断 | 首轮应用提案 | 处理注意 |
|---|---|---|---|
| W1 洞口日出 | 出发、纵深、明暗包围 | 首页或首次进入 | 洞口高亮不放文字；细密材质不穿透正文区 |
| W3 樱花彩虹 | 明亮、轻松、温柔 | 朋友或邀请页面 | 粉色不变成全局按钮色；采用更实的阅读底面 |
| W4 暖阳森林 | 安静、温暖、沉浸 | 世界详情或玩法管理 | 保留斜光与树影，不让光束穿过列表文字 |
| W6 冰峰暮色 | 清爽、冷暖层次 | 偏好设置或性能调整 | 保留天空和地形轮廓，避免大幅裁切后失去主题 |
| W8 官方乘船 | 陪伴、探索、明确的 Minecraft 美术 | 欢迎或新世界引导 | 当前为方形预览，拿到宽屏原图前不承诺最终构图 |

以上页面分配是设计提案，用户只批准了图片偏好。正式使用前检查素材授权与原始尺寸。W1 原作品为动态壁纸，本项目初版按静态场景设计，喜欢该图不等于要求播放视频。

图片处理规则：

- `cover` 只作为基础；每张图单独记录视觉焦点和可放文字区域，不全都用相同中心裁切。
- 只用低强度全局压暗；阅读区域叠加稳定深色面板。模糊解决细节干扰，深色底解决对比，两者不可互相代替。
- 图片预解码完成后切换，避免白闪；失败时保留前一张或纯色底，文字与按钮继续可用。
- 最多保留当前与下一张解码图；按窗口尺寸加载合适资源，不默认解码所有壁纸。
- 不让切页依赖图片加载完成；缩放不做鼠标跟随视差。游戏启动后停止隐藏启动器的场景动画。

## 6. 设计 token v0.1

完整数值以 `design/system/tokens.css` 为唯一 token 来源。以下是主要值及目的，都是本项目的设计初值，**并非从 Lunar/Feather 测量所得，也不是用户已确认的品牌色**。

| 类别 | 初值 | 用法 |
|---|---|---|
| 基底 | `#101316` | 图片失败与窗口底色 |
| 主面板 | `rgba(16,20,24,.82)` + 24 px blur | 深色磨砂整体面板 |
| 弹出层 | `rgba(20,25,30,.96)` + 12 px blur | 提高读写稳定性；不叠加多层实时模糊 |
| 低效果面板 | `#191e23`，无 blur | 低性能和降低透明度模式 |
| 正文 / 次级 / 辅助 | `#F5F7F8` / `#C1C8CE` / `#9BA5AF` | 核心信息不使用低透明度文字 |
| 主动作 | `#A8DDCB`，文字 `#12241E` | 柔和薄荷色初案，连接自然背景与清楚操作 |
| 语义色 | 成功绿、等待琥珀、错误柔红、提示浅蓝 | 始终配图标或文案，不单靠颜色 |
| 中文字体 | Noto Sans SC；平台中文字体回退 | 先保证可读性，正式内嵌前确认资源与许可 |
| 数字字体 | Bahnschrift / DIN Alternate，回退中文字体 | 进度/FPS 使用 tabular-nums，避免数字跳动 |
| 字号 | 12 / 13 / 14 / 15 / 20 / 28 / 36 px | 12 仅辅助信息；主要说明至少 14 |
| 字重 | 400 / 500 / 600 | 用层级表达重要性，避免整页粗体 |
| 间距 | 4 / 8 / 12 / 16 / 24 / 32 / 48 / 64 px | 行内紧凑，段落和任务之间宽松 |
| 圆角 | 控件 10、浮层 16、主面板 24 px | 不将每个列表项包装成大圆角卡片 |
| 操作尺寸 | 图标 20，点击区 44，主按钮高 48 px | 看起来轻，实际容易点击 |
| 阴影 | 主面板 `0 24px 80px black/28%` | 只让真正浮起的表面有阴影 |
| 焦点 | 2 px 浅薄荷 outline + 3 px offset | 无边框不等于没有键盘焦点 |

按钮不必照抄 Feather 红或 Lunar 绿。先用上述单一主色形成一致语言，待首版画面看过后可以整体替换。白字直接压在彩色图片上不是默认方案。

## 7. 控件与状态规则

| 对象 | 默认与交互 | 异常 / 生效语义 |
|---|---|---|
| 主按钮 | 填充主色，短动词；每个任务区域一个主动作 | 禁用时说明原因；执行中显示真实阶段，允许取消时给取消入口 |
| 次要按钮 / 图标 | 无描边、默认透明，悬停出现低对比底色；图标按钮有名称与提示 | 悬停不是唯一发现方式，主要动作保留文字 |
| 导航 | 图标+短标签，选中用浅底色和字重 | 当前项可用语义属性识别；不只靠细小红线 |
| 列表 | 通过列对齐与留白分组，悬停/选中出现背景 | 长名称可换行或查看完整内容，不挤掉状态与操作 |
| 开关 | 只表示能够直接切换的个人功能，改变后立即给结果 | 普通模组修改标注“下次启动生效”；共享包用“提交修改/发布”流程 |
| 搜索 | 搜索图标与示例占位，输入区可见低对比底面 | 空结果显示具体查询和清除入口 |
| 进度 | 下载显示实际已传输量；未知总量显示阶段文字 | 失败在原位置显示修复按钮，不消失后只弹一条 toast |
| 对话 / AI | 保留当前世界和请求上下文；动作结果靠近消息 | 展示影响范围、立即/重载/重启；不可把“代码生成了”当作成功应用 |
| Toast | 短暂成功反馈，可以不打断操作 | 必须处理的错误、授权和失败原因留在任务区域 |

邀请流程保持一个连续面板：收到邀请 → 显示房间与需要准备的内容 → “准备并加入” → 自动检查/下载/启动/连接 → 成功。失败停留在当前阶段，给一个明确修复动作；不让用户手动进入不同管理页拼流程。

HUD 编辑遵循 F3：真实场景预览、拖动、对齐吸附、键盘微调、恢复默认。辅助网格与边界只在编辑态出现；输入焦点在文本框时不能把编辑快捷键送进游戏。面板打开时游戏是否暂停由单人/多人状态决定，不能用视觉遮罩暗示多人世界已暂停。

## 8. 动画语言

| 场景 | 初值 | 目的 |
|---|---|---|
| hover / 按下 | 120 ms | 背景与文字反馈，不移动布局、不让按钮弹跳 |
| 开关 / 状态 | 180 ms | 明确状态改变，结果不依赖动画结束 |
| 辅助层展开 | 240 ms；最多 8 px 平移 + 淡入 | 保留空间关系；返回到触发控件 |
| 一级页面背景 | 480 ms 交叉淡入 | 页面的场景变化柔和；正文可立即交互 |
| 内容切换 | 180–240 ms | 仅轻微位移或淡入，不逐行长时间排队出现 |

默认缓动 `cubic-bezier(.2,.8,.2,1)`；连续背景使用 `cubic-bezier(.4,0,.2,1)`。不动画模糊半径，不常驻粒子/视频/视差；不得让动效阻塞加入或启动。减少动态效果时关闭平移、交叉淡入和装饰循环，状态立即切换。

## 9. 验收方式

### 审美和简单程度

- 分别把首屏与 L1/L2、管理页与 F1/F4、社交与 F2、HUD 与 F3 对照；检查借鉴是否体现在画面，而不是只写在文档里。
- 首屏能立即指出世界名称、主要操作和朋友入口；不能出现多个同权重“开始”按钮。
- 将所有装饰边框隐藏，布局仍然清楚；列表通过对齐和留白可读。
- 所选五种背景逐一检查文字区与裁切；明亮樱花、日出等最亮场景尤其不能漏测。
- 让首次使用者完成“接受邀请并加入”和“打开/关闭 FPS”，记录犹豫点和错误；“极简”以操作表现验证。

### 可读性和实现质量

- 正文对比目标至少 4.5:1；大字和必要控件边界目标至少 3:1。透明色需基于最终合成图像核验，不能只算 CSS 中的底色。当前未声称通过全部背景对比测试。
- 键盘可遍历所有操作；弹窗保持焦点，关闭后还给触发元素；图标有可访问名称。
- 检查 200% 字号/缩放、长世界名、无好友、下载失败、离线、图像缺失与减少动态效果。
- 游戏运行或启动器隐藏后停止装饰动画和无关轮询；单独测量启动器 CPU/GPU/内存，不能以动画顺滑推断不会影响 FPS。
- token 的低效果和降低透明度分支只定义视觉值，组件还须实际实现对应行为；这些文件不表示降级已集成。

## 10. 后续画面产出顺序（2026-10-05 历史提案）

先实现可评审的首页与邀请加入流程，验证整块面板、背景比例和动作优先级；随后扩展玩法/模组、朋友、AI、HUD 编辑。所有页面复用同一 token 和状态语言。示例人物、世界、帧数与连接结果必须标记为演示数据，界面原型不能冒充真正联机客户端。

## 11. 2026-10-06 主页修订（当前优先）

本节覆盖前文中与主页冲突的视觉提案。用户要求当前只做主页，并给出手绘布局：大底板内嵌小面板；中间偏上 Launch + 版本；右侧皮肤模型、手臂切换、皮肤和披风缩略图；下方左侧 News / Mods / Packs / Shaders，右侧 Friends。顶部中间留空、左上角指定开盒 Logo、右上角账号。

删除“Pick up where we left off”等寒暄式文案。主页不再铺满场景壁纸，背景使用连续深灰面板，图像集中在有信息用途的封面。Launch 使用明亮绿色、顶部高光和厚底边建立方块感；标题与操作采用 Barlow Condensed 粗体，ID 和说明采用 Barlow。它们是靠近参考图字形气质的提案，不是已验证的 Lunar 原字体。
