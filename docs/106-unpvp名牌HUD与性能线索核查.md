# unpvp 名牌、HUD 与性能线索核查

日期：2026-11-14 至 2026-11-15。分支：`codex/unpvp-ui`。针对用户提供的 Claude 五项调查截图，检查当前 1.8.9 实现，不将其他版本的发布说明直接套用到 unpvp。

## 五项核查

| 线索 | 当前实现与结论 |
| --- | --- |
| Latency HUD | 旧版读服务器玩家列表的 ping 字段，能解释数字异常，但不能据此解释 FPS。当前已改低频响应估计，见 104/105。HUD 绘制仍有开销，需与测量网络的逻辑分开看。本次单独开关 FPS/CPS/Keystrokes/Ping 四项 HUD，没有按 F1 隐藏名字。 |
| 0.2.20 KeepAlive 循环 | `docs/70` 修复的是好友 VoxLink 的 UDP 心跳互相回送，不是 Minecraft TCP KeepAlive。`ReliableUdpTransport.java` 接收分支仍保留不立即回复的修复；1.8.9 构建脚本从该共享源生成 Java 8 网络组件。普通公共服务器连接不启用好友传输。上一轮本地真实 TCP 测试已经验证主线程阻塞 300 ms 时 KeepAlive 仍可回复，详见 105。没有证据支持这条旧 bug 是当前 Hypixel FPS 根因。 |
| 名牌、Logo 与字体 | 方向相关。`NameBadgeMixin` 每个玩家名字检查身份；`NameBadges.currentView()` 重复规范化 UUID、检查 JSON，识别到用户时还需增加徽章字形。`BadgeFontMixin` 在字体宽度和绘制入口检查局部徽章字符。图片纹理由 `BadgeTextures` 缓存，没有每帧读取/解码 PNG；资源优先级也不代表每个名字重新扫描资源包。普通名字/悬浮文字仍走原字体绘制，不具备完整字体缓存优化。 |
| 性能依赖遗漏/错版 | 本机实验实际加载了 OptiFine M5、Nothirium 0.4.9-beta-2、EntityCulling 6.5、Phosphor、FoamFix、Unbox Patcher 子集及 RenderLib/ConfigurationsBackport 依赖。未发现当前实验漏装这些组件。问题是优化覆盖：Patcher 仅移植 9 个源文件，没有完整字体/HUD 缓存及实体距离优化。截图中的现代版本迁移不是这轮 1.8.9 的直接证据。Windows 用户实例仍需以实际日志核对。 |
| 小地图与持久化地形扫描 | 当前 1.8.9 不提供这些模块，目录与 PvP 回归明确排除 minimap 等生存功能。`Preview.java` 尚有未进入现行目录的旧预览分支，但没有运行地形扫描器，不能把它当作大厅掉帧原因。 |

## 官方对照

[Lunar 官方 FPS 指南](https://support.lunarclient.com/solutions/how-to-fix-fps-issues-in-lunar-client) 明确列出 1.8 专用 Turbo Nametags、HUD Caching 和旧版实体/方块实体显示距离。它也说明 OptiFine 下 HUD 缓存需要关闭 Fast Render。这些可以导致相同区块视距下的效率或实际显示数量不同，但文档没有公开 Turbo Nametags 算法，也没有证明某一个选项必然带来两倍差距。

[Patcher 作者功能清单](https://github.com/Sk1erLLC/Patcher/blob/master/README.md) 包含 HUD 缓存及字体优化。我们的来源子集见 `ports/patcher-performance/UPSTREAM.json`；不能因已安装名为 Patcher 的组件就认为这些全部存在。

## 隔离实验方法

新增 `scripts/test-unpvp.py --badge-cost`，运行现有 `LobbyProbe` 的独立测试分支。使用新测试目录和虚拟身份，不接公共服务器、不读取真实账号或存档。生产功能未改动，测试标志默认关闭。

- Apple Silicon 原生 Java 8，完整性能包；请求窗口 1600×900，Retina 输出，视距 8，VSync 关、不限帧。
- 固定场景：64 个玩家模型、48 条盔甲架悬浮文字，固定位置与朝向。
- 写入与测试身份匹配的有效社交视图，保证执行真实登录状态的身份检查。普通阶段没有其他 Unbox 用户；徽章阶段将全部 64 人标记为 Unbox 用户并轮换三种 Logo，属于密集徽章压力场景，不代表 Hypixel 实际徽章比例。
- 每阶段预热 8 秒，再采约 8 秒帧时间。保持原版名字、模型、悬浮文字；只开关四项基础 HUD。
- 第二个进程加 `--no-badge-hooks`，只在该测试目录的 PvP JAR 副本中移除 `NameBadgeMixin` 与 `BadgeFontMixin`；生产 JAR 不删功能，普通名字仍保留。
- 300 次暖机栈采样在正式帧时间采样前结束；截图在该阶段计时结束后生成。

测试限制：固定顺序短测、单机驱动、合成场景及无正式网络对局；不能将结果作为 Windows / Hypixel / Lunar 的实测增益。关闭徽章的版本仅用于归因，不是交付方案。

## 栈采样与画面核查

普通玩家、有 HUD 阶段，正常版本 300 次暖机采样中，141 次栈包含生物名字绘制路径，105 次包含字体绘制路径，4 次包含 `LiveHud.render`。移除徽章挂钩的对照仍有 110 次包含字体绘制路径。包含关系可能重叠，采样同时覆盖 OpenGL 驱动调用，不能相加或当作精确 CPU 独占耗时。它支持优先检查整个名牌/悬浮文字绘制，而非只追查徽章图片加载。

已查看两组 `badges-no-hud.png`：正常版显示三种徽章，对照移除徽章但保留同样的玩家、普通名字与悬浮文字。测试副本确实移除了两个挂钩；源资源 PvP JAR 的两个挂钩仍存在。测试结束没有删除生产 Logo、名字或 HUD。

## 帧时间结果

运行顺序：正常版 A → 测试移除挂钩 → 正常版 B。各阶段数据为平均 FPS / P95 帧时间（ms）。

| 场景 | 正常版 A | 移除徽章挂钩 | 正常版 B |
| --- | ---: | ---: | ---: |
| 普通玩家，基础 HUD 开 | 179.831 / 8.959 | 199.514 / 7.933 | 182.393 / 8.844 |
| 普通玩家，基础 HUD 关 | 187.607 / 8.733 | 200.652 / 7.707 | 191.481 / 8.650 |
| 64 人徽章资料，基础 HUD 关 | 163.400 / 9.579 | 200.411 / 7.653 | 167.230 / 9.877 |
| 64 人徽章资料，基础 HUD 开 | 159.692 / 9.507 | 196.406 / 8.001 | 161.948 / 9.706 |

解读：

- 没有其他 Unbox 用户时，正常版约 180–182 FPS，对照约 200 FPS。这个场景仍会执行徽章身份/字体入口检查。约 9–11% 的对照差值支持继续优化这些挂钩；不能拆分成某一行代码的确切成本。
- 全部 64 人显示徽章时，正常版约 160–162 FPS，对照约 196 FPS。正常版的密集徽章显示会增加成本；这是压力场景，不能当作真实 Hypixel 全员都有徽章。
- 仅关闭四项基础 HUD，正常版普通场景从约 180/182 提高到 188/191 FPS，约 4–5%；密集徽章场景约 2–3%。这不等于测试了全部原版 HUD 或所有 PvP HUD，也没有测试真实服务器的网络响应耗时。
- 三次运行均完成五阶段、正常退出。每次空场景约 742–783 FPS，只作预热背景，没有拿它与密集场景混算改动收益。
- **没有一个本轮隔离因素呈现两倍差距。** 重点应放在完整名牌/悬浮文字绘制、已有优化覆盖及 Windows 实际渲染路径；不把减掉 Logo 作为最终优化方案。

原始 CSV、截图和暖机栈：`.cache/unpvp-tests/badge-cost-{normal,no-hooks,normal-repeat}/lobby-probe/`。构建和运行摘要：`.cache/unpvp-combat/{build-badge-cost,badge-cost-normal,badge-cost-no-hooks,badge-cost-normal-repeat}.log`。测试脚本 Python 语法检查通过。

## 本轮交付与下一步

只新增可复用的隔离测试和调查文档，没有调整游戏画质、删除功能或发布 Windows 更新。构建生成的核心 JAR 包含默认关闭的测试分支；已打包应用仍是 105 记录的上轮版本。

后续优化应保留普通名字、三种 Logo、现有 UI 与输入反馈：先减少徽章身份的重复字符串处理，再针对文字绘制与 HUD 缓存做单项对照。需要资源重载、昵称/徽章变化、断线重连和动态数字的正确失效机制，不能为了分数缓存过时内容。Windows 的两倍差距仍需用户实际大厅、GPU/分辨率、显示范围及帧时间记录确认。
