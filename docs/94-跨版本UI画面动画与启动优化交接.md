## 3. 画面制作与素材要求

### 3.1 设计、颜色和品牌

- 沿用现有平面矢量设计：组合按钮外侧有圆角，内部拼接边保持直角；分类页签和好友侧栏保留设计中的曲线。不要引入旧磨砂、浮雕、描边卡片或新的视觉风格。
- 使用原始 Unbox 开盒 Logo。浅色面必须镂空，能显示下方背景；保留路径间遮挡关系，不能仅删除白色填充后露出交叉线。
- Outfit 是当前字体资源；静态设计文字轮廓与动态昵称、设置值、搜索输入要分开处理。长文本应裁切或省略，不能溢出；保留字体许可及缺字回退。
- 真实人物预览、皮肤头像、好友和资产状态来自业务数据；不得把原型人物、示例好友、静态 Equipped 勾选或成功画面带进正式业务。
- `.pen` 仅通过 Pen 工具或原生应用访问，不按普通文本编辑。跨机器优先使用仓库中的 SVG 和提取脚本；87 中外部 Pen 路径不保证其他机器存在。

26.3 `SolidTheme.java` 的运行色值如下，迁移时先复用，不凭截图重新猜色：

| 用途 | White / Red | Gray / Yellow |
| --- | --- | --- |
| 背景 | `#E8E8EC` | `#383B3E` |
| 面板 | `#DCDDE2` | `#323437` |
| 主文字 | `#29262F` | `#D1D1C8` |
| 次文字 | `#64606B` | `#AAA99F` |
| 强调色 | `#C9203D` | `#E4B900` |
| 卡片 | `#D0D1D6` | `#383B3E` |

这些是当前实现值；部分 SVG 中有单独的设计填色或旧半透明填色的合成结果，不能机械地全部替换为上表。主题配置为 `ui.theme`：1 / 2；旧 Light 值 0 按 White / Red 读取。

### 3.2 图层与透明度

分为背景层、实心前景、卡片条带、动态控件/人物。`ui.opacity` 为 0–100，应用到背景一次。好友实心面板、按钮、卡片、文字以及 Mods 外框不受此滑块影响。

验证时用 10% 和 90% 背景透明度合成同一场景：背景像素应变化，实心区域像素应保持。Logo 孔洞应显示底层测试色，不能残留白底。

主菜单绘制原版 Panorama，不调用模糊步骤，不生成无用的全屏纯色背景纹理。不要将历史“主底板覆盖窗口”机械套用为重新遮挡 Panorama；仍需保持侧栏和主操作区的布局结构。

### 3.3 渲染实现

当前方案是 **SVG 路径 → Java2D 按物理帧缓冲尺寸抗锯齿栅格化 → 游戏纹理缓存**。它不是每帧实时解析 SVG，也不是 GPU 直接绘制所有矢量路径。

必须保留：

1. 用物理 framebuffer 尺寸生成表面，避免按 GUI 逻辑尺寸生成后放大导致发糊。
2. 静态底图和卡片条带缓存。只有页面、主题、数据、尺寸或布局变化才重建；稳定帧、悬停、滚动和背景透明度变化不逐帧生成全屏纹理。
3. 后台线程只处理不可变绘制快照；GPU 上传与释放使用目标版本要求的渲染线程。一个 worker、一个待处理任务，过期尺寸/状态的结果不得上传。
4. 改尺寸期间旧缓存居中按物理像素 1:1 展示，等待匹配结果；不拉伸旧截图。动态控件不能在新布局上接收旧画面位置的点击。
5. 关闭页面释放表面、卡片新旧纹理，取消后台任务；快速切页不能用过期结果覆盖新页面。
6. 曲线、圆角、蒙版保持抗锯齿。滚动采用亚像素偏移，绘制和命中共用偏移。
7. 只在实际完全遮住世界、缓存尺寸匹配时允许跳过世界渲染。透明背景、缺失表面、露出世界的过渡不能按“菜单打开了”直接跳过。

`VectorScene` 只支持现有导出的 SVG 子集。新增路径命令、滤镜、渐变、蒙版前先检查支持情况，不将其当通用 SVG 引擎。

## 4. GUI Scale 与窗口适配

**Auto 保持现有默认大小；手动档位需要重新安排空间，不能破坏结构。**

- 主菜单账号栏贴左上、退出贴左下，操作组居中；窗口变宽高后重新分配留白。
- 快捷菜单人物在左，操作组居中，好友栏接到右边及上下边缘。好友曲线边缘保持形状，伸长中间连续部分；不要缩成中间一小块。
- 人物高度随空间有限增长，Change skin 跟随人物下沿；人物、中央操作与好友栏互不重叠。
- 好友栏按可用高度计算可见行数，长列表与分页不越界，提示与错误靠近对应内容。
- Mods 外框填充可用区域；按可用宽度计算列数和卡片宽度，按高度改变可见行数。小 GUI Scale 可以看到更多模块，文字和开关仍须可读。
- 模块设置页与 Mods 列表使用同一外框位置、宽高；不能点进设置后突然缩成中央小面板。内部设置列表与预览区随尺寸重排。
- 左侧透明度尺随面板高度延伸，右上主题弧线保持靠右；裁剪矩形、鼠标坐标和控件位置来源一致。
- Appearance 中皮肤、人物、资产分区分别布局，标题和操作跟随所属区域。

26.3 当前实现先用 `sqrt(min(1, selectedGuiScale / autoGuiScale))` 算控件密度，再由 `SolidLayout` 计算区域和列表布局。1440×810 是设计坐标基准，不是必须居中显示的一张固定画布。该公式与数值是实现参考，其他版本须适配其 Auto 档、取整和高分屏语义。

至少检查 Auto / 1 / 2 以及目标版本可用的其他档位、窄窗口、宽窗口、非 16:9、非整除像素尺寸。已有离线测试尺寸包括 3840×2160、2560×1600、1686×958、1280×1024、854×480、3440×1440；离线几何通过不等于这些尺寸均已原生实测。

## 5. 动画与交互规格

下表区分用户要求与 26.3 当前参数。其他版本可适配 API，但应先保持相同节奏，修改参数须有画面和性能依据。

| 场景 | 行为要求 | 当前实现参考 |
| --- | --- | --- |
| 主菜单出现 | 避免突然出现，首次表面就绪后淡入 | 600ms，`1-(1-t)^3`；不为播放动画额外 sleep |
| 悬停、按下、键盘焦点 | 在按钮自己的轮廓内反馈 | `PanelStyle.Motion`：指数趋近，系数 18/s，dt 上限 0.1s |
| 模块开关 | 圆形拇指平滑移动，轨道颜色过渡 | 两个缓存蒙版；46×26 轨道、18×18 拇指、20 UI 单位位移 |
| Mods 滚动 | 连续、平滑、有首尾，到边界停止 | `1-exp(-16*dt)`，dt 上限 0.05s；滚轮每单位目标偏移 112 UI 单位 |
| Survival / PvP | 外框保持固定，标签形状和内容平滑切换 | 标签高度 58↔82；同一指数趋近；卡片条带交叉淡入 240ms，`t*t*(3-2*t)` |
| 主题弧线 | 拇指始终贴线，释放时只停两端 | 鼠标投影与绘制共用曲线；按中点选主题 1 / 2 并保存 |
| 透明度控件 | 连续反馈，只改背景 | 快捷菜单弧线和 Mods 左尺；释放保存；方向键每次 5%，尺上下箭头每次 10% |
| 减动画 | 跳过插值和过渡，直接达到目标状态 | `ui.reducedMotion` 或原版 Screen Effects 为 0；不恢复页脚按钮 |

交互细则：

- 鼠标按下后在按钮内释放才执行；拖出不误触。禁用按钮不执行操作。Tab / Enter、方向键与焦点反馈保留。
- 不显示用户指出的模块开关矩形悬停框和原版 tooltip。移除该框不等于删除全部悬停、按下与键盘反馈。
- 页签、组合按钮、普通圆角按钮的命中区域符合实际轮廓，圆角外不算按钮内部。
- 主题在释放时选择端点并保存，中间位置不是第三种配色；键盘也只能选择两种主题。
- 列表目标位置与绘制位置都限制在 `0..max(0, contentHeight-viewportHeight)`。不要绘制第二份列表来循环；底部不留一整行空白。
- 搜索、分类或列表内容改变后更新滚动范围；GUI Scale 改变也重新夹紧范围。移动后的卡片开关、收藏与设置入口应对应可见卡片。
- 动画只改变表现，不用动画完成时间代替业务成功；快速操作、改尺寸、关闭页面时保持状态正确。

## 8. 启动进度条与已完成的优化

### 8.1 先区分计时边界

用户此次确认慢的是 **Unbox 启动器内的准备进度条**。

| 阶段 | 实际内容 | 注意 |
| --- | --- | --- |
| 点击 Launch → 创建 Java 进程 | 账号准备、检查游戏与库、资源哈希校验、加载器与模组准备 | 启动器进度条覆盖准备阶段，不是游戏完整初始化百分比 |
| Java 启动 → 主菜单可用 | 加载器扫描、模组初始化、资源加载、纹理/字体/声音与 UI 就绪 | 游戏内加载条与启动器进度条是不同阶段 |
| 打开世界 → 可操作 | 世界数据与区块、集成服务器、玩家/画面就绪 | 必须单独测，不能用主菜单启动提速替代 |

目前 `launcher.rs` 的阶段进度为：游戏客户端 5%；库 10–30%；资源按处理数量 30–75%；加载器 78%；性能模组 85%；生存依赖 88%；Java 进程成功创建后标为 `Playing` / 100%。这是一组阶段权重，**不是字节下载百分比、不是剩余时间，也不代表此时已进入主菜单**。

现有 `Downloading Minecraft` / `Installing …` 文案也会出现在本地校验路径；`download()` 哈希匹配就返回，缺失或不匹配才请求网络。不要仅因每次显示进度条就判断重复下载。

### 8.2 三项已经落地的启动优化

1. **调试包的哈希库启用优化编译。**

   `src-tauri/Cargo.toml` 中：

   ```toml
   [profile.dev.package.sha1]
   opt-level = 3

   [profile.dev.package.sha2]
   opt-level = 3
   ```

   原先 debug 中逐个资源的哈希压缩运算很慢。保留启动器调试信息和完整性检查，只优化依赖库。release 原本已优化，不能套用相同提速比例。

2. **已验证的生存模组安装不重复准备下载缓存。**

   `prepare_survival_entries()` 首轮校验记录正确的安装文件；没有共享缓存也能复用已验证安装。打包依赖源仍验证，安装阶段仍复核目标。修改文件、旧版冲突、同名/别名冲突继续按原规则保留或报错，不以性能理由覆盖用户文件。该集合仅用于本次准备，不是跨启动永久信任文件的缓存。

3. **自有客户端 JAR 内容没变就不重写。**

   `write_if_changed()` 比较字节，相同直接返回；变化才原子写入。这样保持文件时间和 inode，避免无意义地破坏加载器可复用的缓存依据。没有因此承诺每个加载器都已有持久化缓存。

这三项主要在共享 Rust 启动器，不应为每个游戏版本复制另一套实现；目标版本新增启动路径时复用相同校验与写入语义。

### 8.3 已有实测，及不可外推的结论

本机 macOS 调试包、缓存资源、测试身份、26.3；各加载器优化前后各两次，实际点击前端 Launch 到主菜单可用：

| 加载器 | 旧版均值 | 新版均值 |
| --- | --- | --- |
| Fabric | 35.09 秒 | 13.31 秒 |
| NeoForge | 39.07 秒 | 13.74 秒 |

Java 创建前约 23.2–26.0 秒降到 0.97–1.85 秒；Java 初始化本身约 11.8–12.8 秒。原始值、阶段日志和哈希在 `research/verification/solid-ui-26.3/startup-fps/`。

这不包含首次下载、真实账号刷新，不代表 release、Windows/Linux、其他硬件或其他版本有相同收益。世界加载本轮未测得改善。

### 8.4 更新包仍然慢时，先检查运行的进程

本会话实际出现：启动器进程于 07:30 打开，新包 08:22 才构建；用户之后从旧进程点击 Launch，仍执行旧的准备代码。构建覆盖磁盘文件不会替换已运行进程。

检查进程启动时间、运行路径、父子进程、构建时间和包内资源哈希。用户保存并退出游戏后，**彻底退出启动器，再打开正确路径的新包**；仅重启游戏不够。不能为了换包强制终止用户世界。

用户随后确认性能模组“未安装”显示已无问题。检查时当前 26.3 Fabric 的六个性能模块均已下载、哈希匹配且被加载器识别，没有为此修改下载逻辑。后续遇到同类问题应核对目标 Profile、真实 mod ID、文件及加载日志，不用文件名或静态列表猜测。

### 8.5 下一步优化应如何推进

- 为实际运行的新版重新分段计时，分清认证等待、磁盘校验、网络、Java 初始化和资源加载，先定位最长阶段。
- 保留未变文件复用；若进一步设计持久化校验缓存，需覆盖内容改变、版本/锁文件变更、缓存损坏和强制重新校验，不能直接关闭校验。
- 游戏进程每次启动仍需建立内存与 GPU 状态；候选模型/资源缓存需要验证失效规则、兼容性和收益，不能简单跳过资源加载或只隐藏进度条。
- 真实进度提示可以更准确地区分检查与下载，但文案改动本身不是速度优化。

以上是后续方向，未实现的缓存或新的提速不得写成当前能力。

## 9. UI 性能经验与候选模组

已实施的 26.3 优化包括：布局/几何缓存、不可见控件跳过、后台首次字体解析、主菜单省去无用背景纹理、模块开关两个缓存蒙版替代 14 次分片提交，以及 Mods 网格的明确绘制层级。

**显式 `nextStratum()` 最终只用于 `VectorModsScreen`。**曾扩展到所有菜单，两轮快捷菜单 FPS 略低，随后收窄。其他版本可能没有该 API，需分析其批处理和层级机制，不能照抄全局插入。

地图优化还有 `WorldMap` 的局部区块/生物群系查询复用，以及 `MapTerrainStore` 最近已加载 tile 复用。移植必须保留脏标记、LRU 淘汰、异步磁盘合并、失败重试及跨世界写入正确性，不能只看地图能显示。

完整默认模组对照中，Mods 列表平均 FPS 约提高 14–16%，滚动约提高 14–20%；世界平均 FPS 在最终两对样本中低约 3%，尚未证实稳定提升，也未排除小幅回退。NeoForge 部分 p99 帧时间没有改善。报告必须同时保留平均 FPS、慢帧和不利样本。

ModernFix、More Culling 未测出足够明确收益，未加入默认配置。C2ME 只完成所记录的短时兼容性检查，未证实性能收益。其他版本需重新核实作者公开发行版本、加载器、许可、依赖和组合兼容性；不能因为在 26.3 启动成功就默认加入其他版本。已有候选版本信息是本次记录，不保证未来仍最新。

## 10. 其他版本的接入顺序

1. **确定基线和源文件。** 保留目标版本当前可用构建；核对本文与最新用户要求，读取目标目录下的协作规则。不要覆盖其他工作区未提交内容。
2. **先适配原生接口。** Screen 生命周期、输入事件、坐标与 scissor、纹理上传、颜色/混合状态、玩家预览、字体、标题替换、资源重载、世界渲染 Hook、Java 版本各自核实。
3. **迁移布局/几何和资源，再接状态。** 先检查两色和比例，再接搜索、滚动、焦点、HUD、真实业务；不以静态截图代替完成。
4. **检查旧版特有渲染问题。** 例如 pose 与 scissor 坐标不同步会截掉列表左侧/顶部；动态纹理状态不正确会使小地图黑屏。分别验证大地图和小地图；Zoom 的键绑定与 FOV Hook 都要成立。用户负责视角体验，助手不增加平滑或滤波掩盖问题。
5. **接动画并验证快速操作。** 页面外框固定、曲线/命中一致、首尾边界和旧纹理释放正确；减动画模式直接完成状态变化。
6. **逐加载器验证，再打启动器包。** 同一截图、同一配置、同一功能分别记录，不把 Fabric 通过等同 NeoForge/Forge 通过。
7. **最后比较性能和交付。** 相同目标版本的修改前后对照，检查运行 JAR、资源 JAR、App 内 JAR 哈希，确认没有测试替换和自动入世界代码被打包。

1.20.1 的 Java 17、其他版本各自要求与映射应以目标运行配置和已有锁文件核实；26.3 的 Java 25 语法/API、`GuiGraphicsExtractor`、纹理后端接口不能原样塞进旧版。避免为一次适配重写全部共享业务。

### 11.1 必须覆盖的行为

### 11.2 26.3 当前复现命令

在仓库根目录执行。这些是 26.3 命令，不是可直接用于任意版本的通用脚本。新名字必须对应不存在的测试目录；两种加载器顺序执行。

```sh
# 只在设计源或提取规则改变后运行；当前只写入 26.3 资源
python3 scripts/prepare-solid-ui.py

UNBOX_MINECRAFT_VERSION=26.3 sh scripts/build-mod.sh

python3 scripts/test-solid-ui.py --loader neoforge --polish-checks --name handoff-polish-neoforge
# 需要完整布局或 HUD 针对性检查时，分别用 --layout-checks / --hud-checks 和新的 --name

cargo test --manifest-path src-tauri/Cargo.toml launcher::tests
npm run tauri -- build --debug --bundles app
```

离线像素/布局测试为 `tests/solid-ui/SolidVisualTest.java`、`SolidLayoutTest.java`，读取实际打包资源；编译/运行类路径应包含当前版本适配类与交付资源。已有证据分别为 367 / 318 项。地图回归源为 `tests/MapTerrainStoreTest.java`；使用测试脚本时先确认实际选中 26.3 覆盖层，不能误测共享旧实现。

性能工具使用方法与限制：

- `benchmark-solid-ui.py` 将 `tests/performance-26.3/FrameBenchmark.java` 编进临时 JAR。依赖已有 `.cache/solid-ui/hud-entry-<loader>/launch-args.json` 和对应运行库；`--fixture` 必须是独立世界模板。`--full-profile` 增加完整依赖；`--world-only` 只测固定视角世界；`--compat-only` 不作为性能结论。
- `benchmark-launcher.py` 的 `build / prepare / run` 在 `.cache/launcher-performance/` 构建一次性源码副本，自动点击真实 Launch，使用虚拟身份；baseline 输入在 `.cache/ui-performance/round2-baseline/`。当前 `run <build-name> --jar <fixture-name>` 的 `--jar` 表示已准备的 fixture 名，和 `prepare` 的 JAR 路径含义不同，使用前读脚本。
- 上述工具含 26.3、本机路径、运行库和源码文本替换假设。迁移机器/版本前要补齐依赖、审查每个替换是否实际命中；不能只改命令里的版本号。
- 不把测试用 `java.awt.headless=true` 加到正常游戏启动参数。测试启动器使用同一 Cargo target 时，最后必须从正式源码重新打包正常应用。

### 11.3 性能对照的最小要求

- 先记录源码/资源哈希和修改前产物。相同游戏版本、加载器、Java、模组、存档副本、位置、分辨率、GUI Scale、画质、距离、内存和焦点状态；不要一边编译一边采样。
- 一次运行一个游戏，区分冷下载、首次准备、缓存启动、真实认证与测试身份。报告启动完整端到端时间和各子阶段，另测进入世界。
- 当前场景预热 8 秒、采样 15 秒；目标版本有更长预热需求时两侧一起调整，重复运行并保留所有轮次。
- 确认真正限帧值：26.3 的 260 为 Unlimited，1000 曾被重置为 120；该数值不能直接推广到旧版。主菜单 60 FPS 与世界/菜单绘制开销分开分析。
- Dynamic FPS 等后台限速影响须控制，两侧同样处理并记录；性能隔离移除不代表从交付默认配置卸载。
- 平均 FPS、p95/p99 帧时间、启动/世界时间、首开长帧分别记录。JFR 用于找热点，其运行与无 JFR 正式数据分开。
