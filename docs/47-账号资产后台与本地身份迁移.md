# 账号资产后台与本地身份迁移

日期：2026-10-19。当前为本地实现与候选包验证，未发布新版 GitHub Release，未将新 Worker 或数据库迁移部署到生产。

## 实现范围

### 身份与数据

- 取消 Unbox 邮箱注册、登录、资料修改入口；旧服务 `/v1/accounts/*` 在新 Worker 中返回 410。
- 旧邮箱身份迁移为本地账号，保留 accountId、UUID、昵称及已有皮肤库关联。先成功保存本地文件，再移除旧会话，迁移可重复执行。
- 本地资料存于数据目录 `local-accounts.json`，皮肤仍在本机皮肤库；改名不会改 UUID。旧邮箱密码、会话令牌不会写进本地账号文件。
- Microsoft 身份经过 Minecraft 认证后，以固定 UUID 保存官方资产与权限。第二台设备重新验证后关联已有平台身份。
- 本地联机使用临时信令身份，云端不保存其昵称或皮肤，显示占位名 OfflinePlayer；私密游戏握手传递真实本地昵称。临时记录和相关关系在闲置 24 小时后清理，因此本地玩家重新联机可能需要重新添加好友。
- 私密房间允许正版／本地身份混合，按 UUID 而非昵称判定房主。普通公开服务器入口限制本地身份；本地 Vanilla 启动会提示需要 Fabric 或 NeoForge。

### 资产后台

后台入口：新 Worker 域名的 `/admin`。独立读写令牌 `ADMIN_WRITE_TOKEN`、只读令牌 `ADMIN_READ_TOKEN`，至少 32 字符；仅管理员配置，不能打进客户端。管理页仅在内存持有令牌，刷新需重填。

- 按 Minecraft UUID 查询账号、有效资产、装备、能力和发放历史。
- 创建／编辑 logo、cape、role，停用目录项，配置角色对应能力 ID。
- 按来源发放永久／限时资产，相同 UUID＋资产＋来源幂等；撤回指定发放记录须填写原因，不影响其他有效来源。
- 账号停用／恢复保留历史资产。资产到期、停用、撤回后不再授予功能或有效装备。
- 服务端装备校验；本地身份无法领取或装备官方资产。
- 操作审计记录。当前管理员是读写／只读两类凭证，尚无多管理员个人账号体系。
- `hasCapability` 供后续付费接口执行服务端权限检查。未加入付费功能，未锁定现有免费功能；披风／logo 的资源制作和客户端展示商城仍按用户要求留空。

### News 与客户端

- 后台 News 支持草稿、定时发布、编辑及撤回至草稿；客户端只显示已到发布时间的 published 内容。
- 启动器启动时及每 60 秒拉取，失败时显示最近缓存，首次失败可重试。无内置新闻替代服务端内容。
- 更新导航按钮仅有可用更新／正在安装时出现，蓝色圆形背景；点击查看日志后手动确认安装。游戏运行时禁止安装。
- Particles 从 Client Mods 和 Mixin 注册中移除，旧配置不会让它重新启用。
- 启动器皮肤头像列左置、五项可见、滚动淡出，悬停展开名称／改名；文件夹入口和导入按钮，Apply 在人物下方。玩家头顶显示 logo、ID，本地显示圈 N 与改名按钮，右侧预留资产。
- 游戏皮肤页移除人物底板和分页等说明，左侧头像滚动点选，右侧留空，Esc／Right Shift 返回。

## 数据与上线顺序

新表定义：`cloudflare/platform-schema.sql`，为增量建表；旧邮箱表暂不删除，避免未迁移用户的数据被提前破坏。

上线时按以下顺序执行，当前尚未执行远端操作：

1. 导出生产 D1 全库备份，记录导出时间、表行数与校验和；把备份放在受限的离线存储，不提交 Git。
2. 在临时数据库恢复备份并执行 platform-schema，验证资产、旧账号和好友关系计数；新系统不得出现空库误接。
3. 配置两类独立管理凭证，确认无凭证返回 401、只读凭证无法修改。
4. 构建并分发候选客户端，检查旧邮箱本地迁移、MS 登录和本地私密联机；新旧握手及邮箱退役需与 Worker 协调切换。不要仅上线 Worker 就宣称现有 0.2.10 已兼容。
5. 进行用户异地测试，参照 `48-异地联机玩家测试清单.md`。
6. 协调发布新版客户端、更新清单和 Worker；再创建第一篇正式 News。旧客户端需明确提示升级。
7. 观察登录、更新、资产查询和房间错误，保留回滚用 Worker 版本与迁移前备份。增量表不要求回滚时删除；已经发生的资产操作应保留，不直接以旧备份覆盖新发放记录。

资产保存依赖数据库运营备份。当前未配置自动异地备份，也未执行生产恢复演练；上线前必须完成。旧邮箱记录清理需等迁移窗口与备份策略明确后另行执行。
