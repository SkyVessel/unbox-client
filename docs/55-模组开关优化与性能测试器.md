# 模组开关优化与性能测试器

本轮在独立 worktree 的 `codex/mod-toggle-audit` 分支实现，基于已发布的 0.2.15（`3b8be11`）。保留另一位 agent 的输入修复；本轮未发布 Release，也未替换主工作区的用户 Profile。

## 开关和配置

- 保留 0.2.15 的 Effortless Building 快捷键和鼠标入口拦截：关闭时不创建菜单，关闭后的清理只在状态转换时执行。回归检查直接调用上游输入回调，在 Unbox 后续清理之前检查是否创建了画面。
- 游戏内录制快捷键遇到冲突时提示占用功能并等待另一个按键。启动器配置导入遇到冲突时保留原绑定并提示原因；不清空其他功能的绑定。Right Shift 仍保留给 Unbox 菜单。
- Unbox 配置使用变更序号；原生适配器在配置或可用状态变化时应用。Spatial GUI 保留双向同步。IPN 每五个 tick 检查原生设置，已暴露的原生开关可以回传到 Unbox；输入权限仍在行为入口立即检查。
- ItemPhysic 配置不再每 tick 重写。IPN 的鼠标拖动和滚轮仍交给 Mouse Tweaks 单独管理。
- 适配器失败后标为不可用，五秒后重试，成功后恢复。新增 Effect Bars 绘制和 Resourcify 入口检查，并补充 Spatial GUI 激活检查，避免仅靠配置同步阻止关闭状态下的行为。

## 运行和保存

- 乐魂速度随乐魂自身服务器 tick 检查；只有速度／骑乘／开关发生变化时修改属性。删除遍历所有维度、所有实体的定时扫描。
- 世界功能配置按不可变快照在后台合并写入，写入失败会保留最新值重试；退出时最多等待三秒。进入世界时仍读取一次很小的世界配置文件。
- 地图待写快照在落盘成功后才移出队列。写入失败后每五秒重试；新的快照会合并旧的待写像素。关闭地图缓存不会丢弃待写内容。持续磁盘故障或直接结束进程仍可能阻止保存，日志会提示。
- 联机共享文件增加协商批量传输：新双方使用最大 768 KiB 分块，旧双方／混合版本仍可使用 256 KiB。低于两种加载器的 1 MiB 登录包限制；身份检查、清单白名单、偏移、总量和最终 SHA-256 校验保留。它减少请求往返次数，仍不是多请求并发窗口协议。

## 性能测试器

入口：**Right Shift → Mods → Performance → Open performance tester**。

- `Record` 开始新记录并清空旧记录；`Stop` 保留结果；`Export` 输出 JSON；`HUD` 控制三行实时摘要（默认隐藏，以降低绘制开销）；`Back`／Esc 返回且继续记录。
- 默认不记录、不采样资源统计。开启后每秒更新一次统计，保留最多 4096 个近期样本用于百分位；平均值和总量覆盖本次记录。
- 显示 FPS、平均帧耗时、p95/p99、Java 堆内存、GC 时间、进程 CPU。
- 大类计时包括游戏客户端 tick、渲染数据提取、渲染提交、内置服务器 tick，以及 Unbox 社交、共享文件后台任务、配置适配、玩法／相机、地图更新、HUD、地图绘制和测试器自身。
- 分类是包含子调用的实际经过时间，可以重叠，不能相加成 CPU 百分比。进程 CPU 是所有逻辑核心的整体占比。GPU 时间和单模组内存不可准确归因，界面明确不提供这些数值。
- Unbox 分类统计插入计时点的自有代码。第三方模组内部开销包含在游戏总耗时里，不能根据某一条适配器耗时判断整个第三方模组的成本。
- 游戏帧统计排除菜单、失焦和暂停状态。对照时保持同一世界、位置、朝向、视距、帧率上限；预热后分别记录约 60 秒，每次改变模组设置后开始新记录。
- 报告位置：对应游戏目录的 `logs/unbox-performance/`。报告包括游戏版本、加载器、Java、操作系统、分辨率、视距、帧率设置和当前模组开关，不导出账号凭证或世界名称。

## 验证

验证记录位于 `research/verification/2026-10-19-performance-audit/`。

本机同一世界副本、固定视角、2560×1440、视距 12、预热 30 秒后记录 45 秒：

| 状态 | 平均 FPS | p95 帧耗时 | p99 帧耗时 |
|---|---:|---:|---:|
| 记录关闭 A | 795.040 | 3.011 ms | 3.323 ms |
| 记录开启，显示 HUD | 764.065 | 3.067 ms | 3.528 ms |
| 记录关闭 B | 795.598 | 3.014 ms | 3.336 ms |
| 记录开启，隐藏 HUD（最终默认） | 788.568 | 3.019 ms | 3.344 ms |
| 关闭记录，与上一行完全相同的 JAR | 792.547 | 3.010 ms | 3.473 ms |

纯记录模式相对完全相同 JAR 的关闭对照约低 0.50%；HUD 显示模式相对前后两次同构建关闭对照的均值约低 3.93%。最后两行和最初三行使用不同构建，分别比较，不混用基线。这是一次固定场景的本机对照，不能推广为所有设备和模组包的固定开销，也不是本轮修改带来的 FPS 增益测量。测试器默认关闭；开启记录后 HUD 默认隐藏。`Profiler snapshot / HUD` 一项只计统计快照和 HUD 绘制，不能代表全部插桩开销。原始逐帧数据以 `.csv.gz` 压缩保存，并记录运行 JAR 的 SHA-256。

完整 Fabric 26.1 功能回归 126 项通过，包括原生模组开关、创造建筑、乐魂速度恢复和召唤、Spatial 人称、原生资源浏览及联机准备取消。六目标最终游戏内回归各 74 项通过（共 444 项），包含输入、快捷键冲突、原生配置回传、故障恢复、实际计时点、JSON 导出和 GUI 缩放；记录见同目录 `*-checks.json`。

独立 JVM 检查覆盖百分位、历史容量、并发计数、世界设置合并及失败重试、地图关闭／重开期间的最新快照保留；损坏单个瓦片目标不会持续阻塞其他瓦片。批量传输测试覆盖旧／新分块的数据一致性及异常输入拒绝。最终六目标重新编译及 `verify-client-bundle.py` 均通过。

边界：本机 macOS 上执行六种游戏版本／加载器组合；不把它们描述为 Windows 游戏实玩或异地网络实测。批量传输检查覆盖编解码与兼容协商，不据此宣称真实公网速度提高三倍。
