# 共享模组、Logo 与性能复查

日期：2026-10-08。范围为 Minecraft Java 26.1 + Fabric 0.19.5，不构建或发布 Release。

## 加入朋友世界

1. 房主正常安装玩法模组、启动世界、邀请好友。访客启动 Fabric Profile 后点击 Join。
2. 保留现有 LAN 优先、e4mc 备用的连接路径。完成 UUID 与邀请口令认证后，在 Minecraft 已加密的登录连接内交换模组清单。
3. 对比当前已启动环境的 SHA-256 清单。完全相同便继续入服，不重启、不传输 JAR。
4. 有差异时，先复用本机当前文件和内容寻址缓存，只下载缺少/损坏的文件。连接页面显示模组和字节进度。每个完整文件校验 SHA-256 后入缓存；失败的部分文件丢弃，完整文件保留供重试。
5. 游戏正常退出后，启动器准备按房主稳定身份区分的好友 Profile，再启动并继续加入。普通 JAR 不能热加载，所以首次同步或模组变更可能需要重启游戏。
6. 好友 Profile 的玩法模组精确匹配清单，房主删除的项不再保留。目录交换有恢复路径，校验失败不会覆盖现有环境。原来的个人 Profile、存档都不更改。

首次创建好友 Profile 会复制原来的 options.txt 与 Unbox HUD/模块配置；后续保留该好友 Profile 中的个人设置。声明为 client-only 的额外 JAR 可保留，Unbox 自带功能与性能 JAR 由启动器管理。没有把所有个人 config、资源包、光影复制给朋友。

## 范围与限制

- 同步 Fabric 中环境为通用的玩法 JAR；排除 Unbox 管理的客户端/性能模块，以及声明为 client-only 或 server-only 的 JAR。嵌入 JAR 的依赖随容器文件一起传输。房主仍须安装其玩法模组所需依赖。
- 这是 JAR 清单同步，不是完整整合包分发：目前不共享自定义 config、KubeJS 脚本、数据包、世界文件、资源包和光影。不支持跨加载器转换。
- 访客额外客户端模组如果依赖房主没有的通用库，仍可能需要手动处理。没有宣称完成通用依赖/冲突解析。复杂整合包及主动拦截登录阶段的模组尚未系统测试。
- 每份清单至多 512 个模组；每个 JAR 至多 512 MiB，总量至多 4 GiB。名称不用于目标路径，目标仅由校验过的哈希构成。不解压远程 JAR。
- 文件哈希/复制放在后台线程，按 256 KiB 请求/响应块传输，每次最多一个未完成块，避免全包驻留内存或堵塞渲染线程。已加入世界后没有持续的模组扫描或传输。仍会有首次扫描、下载的磁盘/带宽开销，不承诺零成本。
- 未变化文件在目录切换时优先复用好友 Profile 内的原文件；缓存按哈希跨次复用。目前没有自动缓存淘汰，缓存会占磁盘空间。
- 邀请有效期仍为五分钟。慢速的大型首次同步可能需要房主重新邀请，已完整下载的文件继续复用。免费公共中继无可用性保证，不能把它描述成无限稳定线路。
- 朋友发来的 JAR 是可执行代码；只加入信任的房主。邀请认证和校验用于来源/传输完整性，不是恶意代码审查。
- Cloudflare 继续仅提供账号、好友与邀请元数据，本轮不需要更新云端，也没有使用 Cloudflare 传输大文件或启用付费服务。

## 实测

- Rust：独立好友 Profile、源 Profile 保留、个人设置保留、删除差异项、缓存保留、路径拒绝、目录交换恢复。
- Java：玩法/client-only/server-only 范围、校验和、重复清单、加载器拒绝。
- 两个真实 26.1 进程：房主独有约 2 MiB 测试玩法 JAR，访客通过真实加密连接下载；调用原生 `sharing::apply` 准备 Profile 后重启，Fabric 确认该 JAR 已加载，入服并持续 100 tick。
- LAN 记录：首次下载 2,097,501 字节，重启后的再次匹配下载 0 字节、无需再次重启。记录位于 `.cache/network-tests/sync-mods-lan/`；报告 `.cache/network-tests/sync-mods-lan.json`。
- 最终 JAR 的 `sync-custom-item-final` 测试还真实注册了 `unbox_sync_fixture:shared_item`，访客从不含该模组的进程完成同步，重启后通过注册表检查并成功入服（Fabric 注册表同步正常）。
- e4mc：`sync-mods-1` 完成相同流程。之后一次公网复测出现公共中继不可用，未冒称为代码测试成功；LAN 复测通过。
- 测试使用同一 Mac 上的两个真实游戏进程及隔离的 Cloudflare 兼容账号服务；不是两地独立网络或生产云端全链路实测。自动启动任务循环已实现，测试驱动程序模拟退出后的编排并调用同一原生准备函数，没有操作用户真实账号/世界。

## 鼠标移动卡顿

用户确认“只移动视角就会卡”，并明确要求找不到可疑点便暂缓，不加平滑覆盖问题。本轮没有改动 MouseMixin，也没有加入输入平滑、滤波或限频。

检查了 26.1 MouseHandler 字节码：onMove 累积位移，handleAccumulatedMovement 再调用 turnPlayer；Unbox 的普通转向路径没有网络请求或磁盘写入。变焦滚轮写设置、配置定时重载、HUD 更新与后台好友轮询分别存在，但没有证据将它们认定为本次鼠标移动卡顿的原因。

目前无法排除物理鼠标/系统/GLFW 与客户端组合的影响，未复现该硬件输入问题，也不声称客户端已被排除。官方 GLFW 输入文档说明事件通过轮询处理：[Input guide](https://www.glfw.org/docs/latest/input)。本轮静态场景帧时间测试不等于物理鼠标测试。

## Logo 与加载器

上次只裁剪 SVG 后，实际 WebView 仍出现偏软。本轮把同一六条原始投影路径直接内联到 SVG，去除遮罩离屏合成，保留 44px 尺寸、原轮廓和深灰底。Chromium 与 WebKit 2× 视网膜截图已检查；WebKit 图在 `.cache/logo-webkit-direct.png`。还需用户在实际屏幕上确认观感。

游戏内 Client Mods、右 Shift、共享邀请/同步目前均为 Fabric 实现。创建界面 NeoForge/Forge 仍禁用并标为 Integration pending，原生创建和启动也拒绝未支持的加载器。Vanilla 可启动，但不包含这些游戏内功能。NeoForge 需要单独移植入口、事件、渲染/网络钩子和依赖，并重新验证，不能给 Fabric JAR 换名来支持。

## 帧时间对照结果

同场景旧 → 新 → 新 → 旧，各预热 30 秒、采样 45 秒，2560×1440，视距 12，所有帧均在前台。旧版平均 557.1 / 590.1 FPS，1% low 155.9 / 162.5；新版平均 549.3 / 580.3 FPS，1% low 149.4 / 158.1。对应平均低约 1.4–1.7%，1% low 低约 2.7–4.1%。未证明性能提升或零开销，差异来源未定位。重复运行本身波动也较大，不能据此认定鼠标或某一模块是原因。原始帧数据、JAR 哈希与完整条件见 `research/benchmarks/2026-10-08-sharing/README.md`。

最终 Node/Playwright 27 项、Rust 24 项、Java 清单检查通过。网络游戏测试为房主 6 项、访客 4 项；测试 JAR 和自定义物品仅存在隔离测试目录，不随应用分发。
