# 兑换码与 Logo 资产库

2026-10-19。用户将邮箱关联改为兑换码，并明确非正版账号不能兑换。[0.2.12](https://github.com/SkyVessel/unbox-client/releases/tag/v0.2.12) 已公开发布为 GitHub latest，继承 0.2.11 的 Mouse Tweaks 开关修复和皮肤库布局。

## 使用

- 启动器和游戏内 Skins 右上角增加 Redeem，输入兑换码领取资产和角色权限。按钮仅供已验证的 Microsoft Minecraft 账号使用。游戏内兑换需要启动器保持运行和连接。
- 人物右侧为 Logos；每个账号默认只有基础 Unbox 图标。服务端已拥有的 Logo 会加入列表，选择后保存装备状态；启动器账号徽章、皮肤页身份图标及游戏内皮肤页跟随选择。
- 已采纳的皇冠／现金图标随包附带：紫盒金冠、金盒绿钞。SVG 直接复用本会话已选定的矢量稿，游戏端使用同稿透明 PNG。美术文件存在不代表获得资产或权限。
- 管理后台的 Redeem codes 可勾选一项或多项资产／角色，创建一次性兑换码、设定兑换期限、禁用未使用码。完整码只在创建时显示，数据库仅存摘要；历史列表不返回摘要或完整码。兑换期限不等于领取后资产到期。
- 没有为任何真实用户发放皇冠或创造者权限，也未签发真实兑换码。皇冠图片不授予管理员能力；创造者身份仍等待用户确认。

## 身份与并发

- `/v1/assets/redeem` 从已认证的服务端身份读取 UUID；忽略请求体里伪造的邮箱、UUID 或 `kind`。非 Microsoft 身份直接返回 403，暂停账号不能兑换。
- 原生层在请求时核对选择的账号，并持有账号锁完成消费；前端丢弃切换账号后的旧响应。
- 每个 UUID 每分钟最多 10 次尝试。兑换码使用密码学随机值，服务端存 SHA-256。
- D1 事务内同时检查未使用、启用、期限、账号状态、全部商品可用性，再认领兑换码、发放全部资产／角色并记录审计。任何失败整体回滚。
- 同一账号重试返回当前权益，不重复发放；其他账号不能再次消费。已撤销的资产不会因重试旧兑换码而重新获得。
- 权限沿用服务端角色 capability 校验；不会将已有免费功能变为收费功能。游戏端的同步文件只负责显示，不作为服务端权限依据。
